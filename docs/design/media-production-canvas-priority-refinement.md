# 媒体生产画布优先体验优化

状态：active design contract

日期：2026-07-17

相关文档：

- [媒体生产画布优先布局](media-production-canvas-first-layout.md)
- [媒体生产体验收口](media-production-experience-refinement.md)

## 1. 决策

媒体生产继续使用全尺寸分镜画布和覆盖式左右 Dock，不回退成固定三栏。左侧项目与场景列表、右侧场景检查器始终悬浮在画布之上；展开和关闭不会改变画布 DOM 宽高，也不会修改场景坐标或顺序。

本合同优化的是默认打开状态、画布安全可视区、命令语义、信息密度和任务辨识度：

- 默认进入已有项目时只打开左 Dock，右检查器保持关闭；
- 只有用户明确点击场景或创建场景时才打开右检查器；
- 面板展开后画布根据可见安全区平移或适配节点，但画布容器不缩小；
- 安全区过窄时左右 Dock 互斥展开；
- MiniMap、批量生成和技术信息按真实需要出现。

本合同覆盖旧合同中“已有选中场景自动打开右检查器”“两个场景开始显示 MiniMap”和“无可运行场景仍保持批量生成主动作”的规则，其余画布、任务和运行边界继续有效。

## 2. 体验目标

1. 画布是默认首屏的最大连续区域，1280x800 下仍可同时看到当前场景和至少一个相邻场景。
2. 配置、结果和历史按需出现，不永久占据创作空间。
3. 付费生成操作必须准确表达本次会提交多少场景；不得出现“生成 0 个场景”的主动作。
4. 场景任务在生成任务列表中可通过项目、场景或提示摘要辨认。
5. 默认层只显示中文产品文案；原始供应商错误、内部 ID 和技术字段进入折叠详情。

## 3. 布局与 Dock

### 3.1 全尺寸画布

`.media-production-canvas-stage` 和 React Flow 画布始终铺满生产台。左右 Dock 使用 stage 内的 absolute overlay：

- 左 Dock：288px；
- 右 Dock：360px；
- rail、Dock、Controls 和 MiniMap 都属于画布覆盖层；
- 展开 Dock 不改变 React Flow 容器的 `clientWidth/clientHeight`。

### 3.2 默认与互斥规则

- 左 Dock 继续使用浏览器本地偏好，首次进入默认打开；
- 右 Dock 不持久化，进入项目、刷新项目或读取已有选中场景时保持关闭；
- 用户点击场景节点、左侧场景行或新建场景后打开右 Dock；
- 若两个 Dock 同时展开后推算的安全宽度小于 640px，打开一侧时自动关闭另一侧；
- 互斥判断基于 canvas stage 的实际宽度，不绑定单一 viewport breakpoint；
- X、rail 和 Esc 继续关闭 Dock，关闭不清除当前场景选择。

### 3.3 画布安全区

Dock 开关、stage 尺寸、场景数量或聚焦请求变化时，Storyboard 重新计算可见安全区：

- 用户明确选择场景时，在保留合理缩放的前提下将目标移动到未被 Dock 覆盖的区域；
- 仅切换 Dock 时，对全部节点执行带左右 padding 的 `fitView`，不只居中当前节点；
- 项目切换、创建和复制场景继续触发聚焦；
- 重复点击已选场景仍可重新聚焦；
- 画布坐标和 `sortOrder` 不因 viewport 调整而变化。

## 4. 画布控件

- 1 个以上场景显示缩放和适配视图 Controls；
- 2 至 4 个场景默认不显示 MiniMap；
- 5 个以上场景，或节点边界明显超出安全区时显示 MiniMap；
- 安全宽度不足以容纳 MiniMap 时自动隐藏，优先保留 Controls；
- MiniMap、Controls、Dock 和顶部工具栏不得相交；
- “位置不影响顺序”继续作为低权重提示，不与右检查器同时争抢底部空间。

## 5. 命令层级

顶部工具栏保留项目入口、`生产台 / 生成任务` 和一个上下文主动作：

| 状态 | 工具栏动作 | 强调级别 |
| --- | --- | --- |
| 未配置视频模型 | 配置视频模型 | 次级 |
| 存在可运行场景 | 生成 N 个场景 | 主动作 |
| 没有可运行场景 | 检查场景 | 次级 |
| 全部已有结果 | 检查场景；重新生成从明确的场景动作进入 | 次级 |

“检查场景”可以打开批量检查面板，但面板不得显示可提交的“生成 0 个场景”动作。批量重新生成不在本轮新增。

## 6. 左侧项目与场景

- 场景行默认只展示编号、名称和紧凑状态；
- 状态使用“已生成 · 上次失败”“已生成 · 批量时跳过”“待完善”等短文案；
- 长解释通过 title/tooltip 或右检查器展示；
- 上移、下移和删除保持紧凑图标按钮与稳定 hit area；
- 项目摘要显示产品模型名称，不显示 provider/model 技术 ID；
- 列表继续内部滚动，不拉长页面。

## 7. 场景检查器

检查器内部使用 `设置 / 结果 / 历史` 三个轻量页内视图：

- `设置`：名称、画面提示、生产方式、模型或流程、比例、时长、参考素材；
- `结果`：当前选用结果、最近一次生成问题和重新生成；
- `历史`：场景运行记录、切换当前结果和取消运行；
- 点击场景默认进入设置；点击节点预览继续打开独立预览弹窗；
- 场景已有当前结果时，“结果”显示可见状态点；
- 原始错误放入默认折叠的“技术信息”，默认错误使用中文原因和下一步动作。

检查器 footer 的单场景生成动作保持可见，不因页内视图切换而消失。

## 8. 生成任务身份

不修改 Media Job schema。Web 使用当前已加载的项目、场景和 Scene Run 建立只读任务上下文：

- 能关联当前项目场景：标题显示 `项目名 · 场景名`，说明显示提示摘要；
- 无法关联的独立任务或其他未加载项目任务：标题显示提示摘要，操作类型作为辅助信息；
- provider、创建时间和结果数继续作为 metadata；
- 不向任务对象写入项目名或场景名。

## 9. 生产流程空态

没有可管理流程且没有导入草稿时，流程页使用单一居中空态：

- 只保留一个“导入流程”动作；
- 隐藏空列表头、重复加号和空白详情栏；
- 没有连接时点击导入仍进入连接页，不改变现有安全检查；
- 存在流程或导入草稿后恢复列表与详情双栏。

## 10. 模块边界

| 模块 | 责任 |
| --- | --- |
| `MediaProductionWorkspace` | Dock 状态、互斥规则、任务上下文装配 |
| `StoryboardCanvas` | stage 测量、viewport 安全区、MiniMap 可见性 |
| `MediaProductionCanvasToolbar` | 上下文动作标签与强调级别 |
| `ProjectSceneOutline` | 紧凑场景列表，不读取布局状态 |
| `SceneInspector` | 页内视图装配，不直接请求 API |
| `media-production-view-models` | 状态短文案、错误产品化、任务上下文纯函数 |
| `WorkflowLibraryWorkspace` | 空态与既有流程列表装配 |

不把 UI 布局写入 `use-media-production-controller`，不修改 daemon、API client、SQLite 或 Media Job 数据契约。生产源文件继续保持低于 800 行。

## 11. 验收

- 1440x1000、1280x800 下 Dock 是覆盖层，画布容器尺寸在开关前后相同；
- 进入已有项目时右 Dock 关闭，显式点击场景后打开；
- 安全区不足时左右 Dock 不同时展开；
- 两场景不显示 MiniMap，五场景显示 MiniMap；
- Dock 开关后当前节点和相邻节点不被覆盖；
- 没有可运行场景时工具栏不显示批量生成主按钮；
- 检查器可切换设置、结果和历史，默认层不显示 `fetch failed`；
- 当前项目生成任务显示项目与场景身份，独立任务显示提示摘要；
- 流程空态只有一个导入动作且没有空白详情栏；
- Esc、预览、删除、排序、单场景生成和任务重试不回退。
