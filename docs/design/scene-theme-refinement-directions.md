# Breeze、Ocean、Night 主题细化方向提案

状态：三套方向已获用户认可，摄影风格实施中，2026-10-27。用户明确要求替换初版简易卡通，优先更真实的图片；不能把方向稿或自动测试视为美术验收。

关联：[官方主题系统](ui2.0升级/themes/README.md)、[统一主题合同](theme-background-motion-contract.md)、[阅读与播放合同](theme-background-hardening-plan.md)、[Journey 组件适配方案](ling-journey-ui-adaptation-implementation-plan.md)。

## 目标与现状

当前 Breeze、Ocean、Night 已有 SVG 场景、语义配色和共享背景能力，但尚未按套完成背景美术、组件材质、内容状态与专项视觉验收。此次细化保留“两浅一深”的结构，分别覆盖自然温暖、海边开阔和夜间安静三种工作氛围。

采用方向为 **Breeze · 林间晨光、Ocean · 海盐晴空、Night · 雨夜书窗**。继续使用既有 theme ID，保留偏好与选择记录。

## 三套推荐方向

| 主题 | 场景构图 | 色彩与 UI 材质 | 工作氛围 |
|---|---|---|---|
| Breeze · 林间晨光 | 清晨林地、斜照日光、树影、薄雾与通向远处的小径；细节集中在边缘和右侧，中央保持柔和留白 | 暖白与淡鼠尾草绿作为基础，深松绿主操作；侧栏轻灰绿，输入框呈温润纸面，浮层为清晰暖白 | 明亮、自然、适合日间长时间阅读 |
| Ocean · 海盐晴空 | 临海高地或白色海岸、远处岛屿、低处海平线与大片天空；海面反光避开文字区，可用一艘小帆船提供尺度 | 海盐白、浅蓝灰与低饱和海蓝；输入框为瓷白，主操作用深海蓝，边框和分隔线偏冷灰 | 通透、开阔、轻盈，适合规划与协作 |
| Night · 雨夜书窗 | 室内望向窗外的雨夜，窗外为失焦城市或庭院灯光，角落一盏台灯；中心为安静暗部，窗框避开主要内容区 | 石墨灰、少量暖棕与琥珀灯光；内容面板为暖深灰，主操作用克制的琥珀色，浮层增加明度而非泛光 | 安静、有生活感，适合夜间写作与专注 |

三套优先采用摄影风格的完整画面，使用自然光、真实材质、合理透视与空间层次。停止沿用初版 SVG 几何树木、波浪、机器人叠加。用户接受免费许可图片或图像模型生成；本轮使用内置 imagegen，新图不是实拍照片。工具没有模型选择参数，不能声称使用了用户提到的 gpt-image2.5。母图、提示词、生成来源和导出摘要留档。

构图按当前工作区优化：侧栏所在左侧和中央正文区保持平静，主景细节集中在边缘及右侧；明亮场景不以强光穿过主要文字区。以静态 WebP 提供背景与同源缩略图，整张图不再叠加独立角色。若以后尝试卡通，需达到用户所指 WorkBuddy 的精细插画水准，并另行做参考与视觉稿。

### Night 备选：月下观星

若继续采用现有星空题材，可细化为“月下观星”：远山、月光、极少量星点和低亮度极光，UI 使用深靛蓝、冷银灰与月光蓝。它与现有 Night 的迁移较直接，但应通过天空层次、冷色材质和主操作色，建立与 Ling Dark、远行问剑各自明确的辨识度。

优先推荐“雨夜书窗”，理由是六套主题中目前已有基础深色与远行问剑的宏大外景，温暖室内场景能补充另一种夜间体验。最终取舍由用户的氛围偏好决定。

## 必须同步细化的 UI

每套以同一组界面完成设计，沿用既有布局与交互：

1. **首页与 Shell**：背景构图、侧栏/顶栏/rail 材质、原 Logo 可读性、首页标题与快捷入口。
2. **输入框与主操作**：输入面板、工具栏、发送按钮、选中/hover/focus/disabled 状态。
3. **三类会话**：普通会话、频道、队友私聊的正文实底、用户消息、代码、引用、表格与提示；布局层透明，工作页背景继续自动减弱。
4. **管理页面**：插件行、自动化、模型工作台、队友列表的内容层级与空白区域。
5. **设置和弹层**：设置实底、主题卡、Menu/Popover/Dialog/Toast、错误与成功状态、键盘焦点。

自然绿、海蓝与琥珀主色不能替代业务状态的语义。尤其 Breeze 中的成功态、Night 中的警告态，需要同时通过图标、文案、边框和语义色区分。正文目标对比度至少 4.5:1，有意义的图标和焦点至少 3:1；拟定颜色经检查后才能定为正式 token。

## 共用边界

- 保留原项目 Logo；场景不要求放入新的品牌 IP。若加入人物、动物或小船，须融入整张背景的光影与尺度。
- 首轮先把静态画面与 UI 材质定稿。后续若增加动态版本，复用已完成的共享播放、减少动态效果、暂停和静态回退策略。
- 内容布局、字体系统、控件尺寸与操作方式沿用当前产品；主题差异主要由背景、语义色、材质、边界和阴影表达。
- 原有全局自定义媒体及每主题 opacity/focus/paused 数据继续生效。设计稿的官方背景展示在隔离预览中进行，避免用户现有花卉 MP4 遮住候选画面，也不清除当前用户媒体。
- 远行问剑、Ling Dark、Ling Light 作为回归基线；本提案尚未改变它们的已验收实现。

|---|---|

| D2 Breeze 试点 | 先用一套浅色主题校准暖白内容层、背景亮部和控件状态，再复用成熟规则到其余主题 |

正式实施主要归属 `packages/ui-react/src/theme/built-ins/ling-{breeze,ocean,night}.ts`、`packages/ui-react/src/styles/themes/built-in-themes.css`、共享 presentation profile、Web `styles/base.css` 兼容变量映射、`SceneArtwork.tsx` 与 `apps/web/public/themes/`。Feature 只消费共享变量，不增加按 theme ID 分叉的业务 UI。已有背景仓库、profile 模型和保存事务不因美术细化而改变 schema。

主题名称或说明若调整，使用现有 localization 流程。每套的验收记录分开维护，标明使用的母图/导出资源、源码摘要与真实浏览器证据；当前共享测试结果不能替代尚未执行的独立主题视觉验收。Desktop 发布门槛继续按既有背景验收矩阵执行，移动端不在本轮范围。

### 实测补充：浅色主题的兼容变量映射

2026-10-27 在真实浏览器发现：`base.css` 只有深色选择器把 `--text`、`--accent`、`--conversation-code-bg` 等旧组件变量映射到 `--ling-*` 语义变量。Breeze/Ocean 的共享控件已换肤，但部分旧组件仍用默认浅色配色。此次把这两套浅色主题接入同一个兼容映射块；颜色模式和深色 Composer 阴影仍保留独立声明，Ling Light 原有样式不变。不向频道/队友/普通会话添加重复主题规则。专项浏览器检查同时读取兼容变量和语义变量并比较，以避免仅检查主题根节点而遗漏旧组件。
