# Ling 产品待做清单

> 汇总自用户关于 DeepSeek Harness、dsh-purge、自动化、版本更新、MCP、插件与语音的需求。状态以当前仓库实现为准，未把已有能力重复列为“从零开发”。

## 结论速览

- **自动化调度**：已有主干能力，支持持久化定义、草稿、运行记录、调度器、手动运行和审批；仍需补齐桌面通知、丰富监控源、外部投递与外部动作提案。
- **版本号与更新提示**：`VERSION`、根 `package.json`、Desktop、Web、daemon health 与 CLI 当前统一为 `0.3.0`；daemon 协议版本为 `1`。已有 GitHub Releases 稳定版本检查、设置页手动检查、发布页跳转、tag 触发的 Desktop Draft 构建，以及 Desktop 对 daemon 产品/协议不匹配的更新提示；自动下载/安装尚未启用。
- **插件与 MCP**：已有内部/内置插件管理、MCP preset、状态与健康检查；社区插件市场和用户一键安装仍是后续阶段。
- **dsh-purge**：当前应作为独立实现/兼容层评估，先做能力拆解和授权、发行、运行时耦合核查，再决定集成方式。
- **语音交谈**：协议层已有 audio 内容类型与音频模型目录，但端到端录音、语音识别、语音合成、连续对话 UI 尚未形成完整产品闭环。
- **跨 App 自动化**：Ling 已有自动化执行与桌面 Computer Use/MCP 基础；日历、提醒事项、备忘录等系统 App 需要新增受控原生适配器和工具目录。

## P0：基础产品闭环

### 1. 统一版本号与更新提示

**目标**：GitHub 发布新版本后，旧版 Ling 能提示用户。

**当前基线**：

- Desktop package 已有 semver 版本号。
- 已有稳定 GitHub Release 查询、版本比较、24 小时节流、中文提示和发布页跳转。
- 当前策略是“提示 + 用户手动下载”，不自动下载/安装。

**待做**：

- [x] 统一 Web、Daemon、Desktop、CLI 的产品版本；daemon health 与 CLI 同时显示协议版本。
- [x] 在设置页增加“当前版本、检查更新、最近检查时间、发布说明”入口。
- [x] GitHub Release 工作流支持正式 tag 触发双平台构建并创建 Draft；签名、验收和最终 Publish 仍由维护者执行，更新检查会发现已发布的稳定 Release。
- [x] 增加 daemon/client 产品或协议不兼容时的“需要更新 Ling”提示。
- 后续可选：签名校验后的自动下载与安装；先保持手动安装策略。

**验收**：旧版本读取新稳定 Release 后出现一次提示；草稿/预发布不触发；网络失败不影响启动；版本号和 Release tag 一致。

### 2. 自动化：允许给其他 App 发指令

**目标**：用户说“帮我把这件事放进日历/提醒事项/备忘录”，Ling 能生成结构化动作，经确认后执行。

**首批 App**：

- macOS Calendar：创建、查询、修改、删除事件。
- macOS Reminders：创建、完成、修改、删除提醒。
- macOS Notes：创建、追加、搜索、打开备忘录。
- 后续扩展 Windows Outlook/To Do/OneNote，移动端系统日历和提醒。

**实现要点**：

- 新增 `native-apps` 深模块：统一列出 App、能力、参数 schema、可用性和执行结果。
- 每个动作先形成结构化预览，再走现有审批/确认链；写操作默认逐次确认。
- macOS 优先使用原生 EventKit/系统桥接；AppleScript 仅作为受限适配器，参数通过 argv/结构化数据传递。
- 所有动作写入审计记录，支持取消、重试、幂等键和失败恢复。
- 自动化调度可调用这些工具，但外部副作用必须保留审批策略。

**验收**：自然语言生成正确动作预览；用户确认后写入真实 App；重复运行不重复创建；拒绝/取消有明确记录。

## P1：插件与 MCP 生态

### 3. 内置插件推荐源 / 社区插件市场

**目标**：用户打开插件页即可看到推荐插件，不必手动填写地址源，点击安装即可用于 Ling。

**当前基线**：内部/内置插件管理、MCP preset、插件状态与健康检查已有；设计文档明确第三方插件 API、市场安装与不受信任沙箱尚未完成。

**待做**：

- 建立由 Ling 官方维护的内置 catalog（版本、平台、来源、许可证、权限、MCP servers/tools、配置字段、健康检查、更新策略）。
- 插件页分为“推荐、已安装、可更新、手动添加”；支持搜索、分类、详情和安装前权限预览。
- 首期只允许 manifest + MCP/skill/config 资源，不直接加载任意代码。
- 安装到本地 cache，记录来源、版本、摘要、校验和、安装时间；支持卸载、禁用、回滚。
- 支持用户自定义地址源作为高级入口，但默认无需输入。
- 引入插件更新检查、兼容性检查和迁移提示。
- 后续再开放受限第三方插件 SDK 与隔离运行时。

**验收**：干净工作区能加载官方 catalog；安装 GitHub/MCP preset 后可在插件页看到健康状态；工具必须显式分配并经过审批；来源和权限可追溯。

### 4. MCP 一键连接与使用

**目标**：从插件详情直接连接 MCP，自动完成配置、密钥引用、工具同步和分配。

**当前基线**：MCP server CRUD、secret refs、check、status snapshot、sync tools 已有。

**待做**：

- 插件 manifest 声明 MCP transport、环境变量/Keychain 引用、必需权限和推荐工具。
- 连接向导：选择本地进程/远程 HTTP/SSE → 填配置 → 密钥引用 → 检查 → 同步工具。
- 在会话/队友配置里提供“启用本插件工具”的清晰入口。
- 连接失败给出可操作诊断；密钥只显示 ref，不回显 secret。
- MCP 工具支持按插件批量启停、版本兼容和健康刷新。

**验收**：一键连接后工具可被显式绑定；断线、重启、刷新后状态一致；secret 不出现在日志/UI。

## P1：Harness 能力对齐

### 5. Harness 模式体系

**目标**：参考 DeepSeek Harness 的标准模式、PTC 模式、极简模式、创意模式、Red team mode，在 Ling 提供可理解、可配置的运行模式。

**待做**：

- 建立 `RunMode` 配置模型：工具集合、权限预设、上下文压缩、并发、审批、输出风格。
- 首期提供：标准模式、工具调用模式、极简模式、创意模式；Red team 作为内部评测模式，单独权限档案。
- 模式切换只改变运行配置，不绕过 daemon、审批、MCP 和审计状态机。
- 会话中显示当前模式，保存到运行快照，支持工作区默认值。
- 为每个模式补齐 UI、schema、迁移和测试。

**验收**：切换模式后新运行使用对应配置；旧运行可复现原配置；模式不会隐式扩大工具权限。

### 6. dsh-purge 集成评估与实现

**目标**：把 dsh-purge 的有价值能力带入 Ling，而非直接复制 DeepSeek Harness 私有实现。

**阶段 A：拆解与决策**：

- 盘点 dsh-purge 的功能边界：提示词/配置清洗、shim、override、引擎级审批/沙箱处理、备份与回滚。
- 核查源码许可证、第三方依赖、与 DSH 私有路径/协议/构建产物的耦合。
- 形成能力映射：哪些属于 Ling kernel、plugin host、approval policy、runtime adapter、release tooling。

**阶段 B：Ling 原生实现**：

- 把可复用部分改造成 Ling 的配置迁移/校验模块，提供 dry-run、差异报告、备份和回滚。
- 将审批、沙箱和工具授权接入 Ling 现有 kernel，不注入绕过逻辑。
- 增加 CLI：`ling doctor` / `ling config check` / `ling config repair --dry-run`。
- 所有修改可审计、可恢复，禁止直接覆盖用户密钥和工作区数据。

**验收**：在测试 workspace 上可重复运行；失败可回滚；不依赖 DSH 安装路径；测试覆盖配置损坏、旧版本迁移、部分失败。

## P1：语音交谈

### 7. 语音输入、语音输出与连续对话

**目标**：像 OpenClaw 一样支持按住说话/点击录音、语音识别、模型回答后语音播报，以及打断和连续交谈。

**当前基线**：底层协议可承载 audio，已有音频模型记录；产品端到端语音交互尚未闭环。

**待做**：

- Web/desktop/mobile 录音控件：权限申请、录音状态、波形、取消、重录、上传。
- STT adapter：系统识别或配置的云端/本地模型；统一 transcript schema。
- TTS adapter：按 provider/model/voice 配置；流式播放和停止。
- Conversation pipeline：audio input → transcript → normal run → audio output。
- 支持 barge-in（用户说话打断播放）、暂停/继续、失败回退文字。
- 录音文件默认短期临时保存，用户明确保存才进入工作区 artifact。
- 在设置中管理麦克风、扬声器、语言、语音、自动播放和隐私选项。

**验收**：桌面端可完成一次完整语音对话；播放中可打断；无麦克风/网络失败时文字流程继续；不会把临时录音泄漏到日志。

## P1：品牌与动效

### 10. Electric Logo 动效

**参考**： [React Bits Electric Logo](https://reactbits.dev/animations/electric-logo)

**目标**：将 Ling Logo 改造成带电流/霓虹能量感的品牌动效，用于启动页、空状态、登录/欢迎页和桌面应用图标周边的品牌展示。

**待做**：

- 评估 React Bits 示例的实现方式、依赖、许可证和生产构建体积。
- 抽取为 Ling 自有 `AnimatedLogo` 深模块，接口只暴露尺寸、主题、播放状态和降级模式。
- 支持静态 logo、hover/页面进入动效、循环播放和 reduced-motion 降级。
- 适配 Ling 当前深色主题、蓝色品牌色和浅色主题。
- 首批接入启动页、Web 空工作区、插件页空状态、桌面启动/更新提示。
- 处理高 DPI、低性能设备、窗口隐藏/后台暂停、SSR/截图测试和无障碍标签。
- 保留静态 SVG/PNG fallback，避免动效失败影响主界面加载。

**验收**：Web 与 Desktop 显示一致；启用 reduced motion 时保持静态；动效不会持续占用后台资源；构建产物体积和帧率达到发布门槛；保留品牌静态资产作为回退。

### 11. Electric Border 思考等级特效

**参考**： [React Bits Electric Border](https://reactbits.dev/animations/electric-border)

**目标**：当模型的思考等级达到最高档时，为对话框或消息输入区域显示电流边框特效，强化“高强度思考中”的状态反馈。

**触发规则**：

- 仅对声明支持思考等级的模型启用。
- 只有当前思考等级为该模型支持的最高等级时触发。
- 模型未返回思考等级、仅支持普通对话或处于错误/取消状态时保持普通边框。
- 特效状态由真实运行配置驱动，不根据 UI 文案猜测。

**待做**：

- 评估 React Bits 示例的依赖、许可证、Canvas/CSS 实现和生产构建体积。
- 抽取为 Ling 自有 `ElectricBorder` 深模块，接口只接收 `active`、`intensity`、`theme`、`reducedMotion` 和尺寸。
- 将模型能力映射为统一 `reasoningEffort`：`none`、`low`、`medium`、`high`、`xhigh` 或 provider 自定义等级。
- 在模型选择器/思考等级控制中明确显示最高档标识。
- 思考开始时平滑进入，思考结束、取消、报错或降级时平滑退出。
- 支持深色/浅色主题、低性能设备、窗口后台暂停和 `prefers-reduced-motion` 降级。
- 避免影响输入框可读性、焦点环、键盘操作和无障碍状态播报。
- 增加截图、交互和状态机测试，覆盖最高等级、非最高等级、模型不支持、取消和错误路径。

**验收**：最高思考等级开始运行后对话框出现电流边框；其他等级不出现；停止后边框消失；切换模型与模式不残留旧状态；reduced motion 下使用静态强调样式。

### 12. Ling 开机动画

**目标**：在 Ling 启动、桌面应用加载和必要的重启恢复阶段提供统一的品牌开机动画，使用 Electric Logo 等品牌动效作为视觉入口，同时明确反馈启动进度和异常状态。

**待做**：

- 设计启动动画时间线：品牌 Logo 出场、能量/电流效果、加载完成和进入主界面过渡。
- 复用 `AnimatedLogo` / `ElectricBorder` 的视觉语言，统一 Web、Desktop 和后续移动端的品牌体验。
- 区分冷启动、热启动、daemon 连接中、恢复工作区、更新后首次启动和启动失败等状态。
- 绑定真实启动阶段：daemon、配置、插件/MCP、工作区和 renderer ready；不使用固定延迟伪装完成。
- 支持最短展示时长与快速设备跳过策略，避免启动过慢；后台恢复时降低动画资源占用。
- 提供 `prefers-reduced-motion`、低性能设备和无障碍降级方案，保留静态 Logo 与进度文本。
- 增加启动失败、超时、daemon 不可用、插件恢复失败和重试入口。
- 覆盖 Electron clean launch、daemon 重启、窗口重载、更新后启动、截图和性能测试。

**验收**：开机动画能准确进入主界面；真实 ready 状态完成前不会提前结束；启动失败可见且可重试；reduced motion 下使用静态 Logo/进度；动画不会阻塞 daemon 或主界面交互初始化。

## P2：体验与生态完善

### 8. 自动化与系统 App 的组合模板

- “每天 9 点读取日历并生成简报”。
- “把对话中的待办加入提醒事项”。
- “把会议纪要追加到指定备忘录”。
- “每周五汇总项目进展并写入 Notes/文档”。

每个模板都应复用 AutomationDefinition、普通 Run、MCP/native tool、审批和 artifacts，不另起一套任务系统。

### 9. 插件市场运营与发布流水线

- GitHub 仓库/Release 自动生成 catalog 条目。
- CI 校验 manifest schema、许可证、权限声明、平台兼容性、MCP health check。
- 插件评分/下载量/最近更新仅作为发现信息，不能替代来源和权限展示。
- catalog 签名、缓存、回滚和下线机制。

## 建议实施顺序

1. **先做版本与更新体验收**：已有大半实现，补 UI/发布资产/协议提示。
2. **做跨 App 自动化最小闭环**：macOS Reminders + Calendar 两个写入动作，接现有审批。
3. **做 MCP 一键连接**：把已有 MCP routes 与插件详情/向导串起来。
4. **做官方内置 catalog**：先 manifest + MCP preset，暂不加载任意代码。
5. **做 Harness 模式**：把模式变成 RunMode 和权限预设。
6. **做语音 MVP**：桌面录音 + STT + TTS + 打断。
7. **最后处理 dsh-purge**：完成源码/许可证/耦合评估后，选择原生重写或隔离适配。

## 当前不应直接承诺的事项

- 任意社区代码一键安装并直接在主进程运行。
- 将 dsh-purge 的内部 shim/override 原样复制进 Ling。
- 语音能力覆盖所有平台、所有 provider 和离线场景。
- 自动下载并静默安装桌面更新。
