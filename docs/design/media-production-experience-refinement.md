# 媒体生产体验收口

状态：active contract；Web 生产台体验收口已实施

日期：2026-07-14

范围：桌面 Web 的媒体生产台、生成任务嵌入视图、视频结果预览、场景批量生成前确认

相关文档：

- [模型工作台视频生产台](model-workbench-video-production-studio.md)
- [媒体与自动化工作台收口](media-automations-workbench-refinement.md)

## 1. 产品问题与目标

当前实现已包含场景准备度、生成前 review、`sceneIds` 选择性批量提交、服务端全部验证后零副作用创建、
项目/场景顺序管理、真实视频预览和结果选择。后续回归直接以本合同和媒体生产测试为准，不再维护实施流水。

Ling 已经能从模型工作台真实生成视频，但当前生产台仍像一组刚接通的工程控件：项目选择和名称重复、空画布过于空旷、场景没有可扫描的顺序列表、批量生成缺少准备度检查，视频结果也被当作普通文件展示。

这轮目标不是增加剪辑能力，而是让用户可以平静地完成这条已有真实能力的创作路径：

```text
选择项目 -> 组织场景 -> 填写画面与模型 -> 确认将要生成的场景 -> 查看并选用视频结果
```

成功信号：首次进入能理解下一步；多场景时能看清顺序、准备情况与选中结果；生成前不会意外提交未完成场景；视频任务完成后能直接观看，不需要通过通用文件链接猜测结果。

## 2. 边界

### 本轮包含

- 项目、场景、分镜画布、场景检查器和生成任务页的信息层级与交互收口；
- 场景顺序列表与明确的上移/下移操作；
- 视频 artifact 的内联预览、播放、打开与下载入口；
- 批量生成准备度摘要与确认，不提交尚未准备好的场景；
- 面向任务视图的紧凑嵌入工具栏、中文状态与低噪详情。

### 明确不包含

- 时间线、拼接、转场、字幕、配音、FFmpeg、成片导出；
- 外部工作流、第三方媒体平台、URL 工作流或未验证模型；
- 参考图能力扩展。Seedance 仍只显示真实可运行的文本视频输入；
- 聊天、频道、AI 队友的模型选择或生成语义变更；
- 移动端专项验收。

## 3. 信息架构与布局

入口仍为“媒体生产”，页内只有两个视图：

| 视图 | 用户任务 | 主体 | 次要内容 |
| --- | --- | --- | --- |
| 生产台 | 组织和生成分镜 | 场景序列、画布、场景检查器 | 项目设置、运行历史 |
| 生成任务 | 查看独立任务与结果 | 任务列表、视频/图片结果详情 | 原始诊断 |

### 3.1 顶部页头

页面只保留一个“媒体生产”页头和页内 tabs。它说明当前视图的工作目标，不重复承载 tab 内的同名大标题。

- 在“生产台”时，右侧只有刷新和“新建项目”；
- 在“生成任务”时，页头不显示“新建项目”，任务区自己的紧凑工具栏提供“创建生成任务”；
- 页面标题下方只保留一行与当前 tab 相关的说明，不能显示技术实现或重复统计。

### 3.2 生产台三栏

生产台使用固定高度的三栏工作台，所有长内容在各自栏内滚动：

```text
项目栏与场景序列  |  分镜画布  |  场景检查器
220-248px          |  minmax    |  340-380px
```

1. **项目栏与场景序列**
   - 顶部用一个项目选择器呈现当前项目；名称只在同一处编辑，不能同时出现相同的“项目名称”输入框；
   - 项目重命名和默认模型是低频项目设置，收在“项目设置” disclosure 内；关闭时只保留项目选择器与当前默认模型摘要，避免项目名重复占用首屏；
   - 下方按 `sortOrder` 展示场景 01、02、03。每行显示标题、准备状态、当前结果状态；
   - 场景行是主点击目标；上移/下移是明确的图标按钮，禁用状态可见；拖动画布永远不改变顺序；
   - “添加场景”在该栏的标题行，避免和生成动作混在项目设置区。

2. **分镜画布**
   - 画布只负责空间编排和选中关系。节点显示编号、标题、提示词摘要、比例/时长、准备或结果状态；
   - 节点不塞表单和低频动作；节点状态不能只写“有历史”，需要区分未准备、可生成、生成中、需处理、已有当前结果；
   - 空项目时，画布空态的唯一主动作是“添加第一个场景”；避免“新建项目”“添加场景”同时争夺注意力；
   - 画布角落的“位置不影响生成顺序”说明维持低权重，只在有两个及以上场景时显示。

3. **场景检查器**
   - 选中场景后，按“画面提示 -> 模型与参数 -> 当前结果 -> 历史记录”的顺序显示；
   - 名称和提示词失焦即保存；保存中只影响当前字段，成功反馈通过全局 2 秒提示显示，不能覆盖画布标题、场景数量或生成按钮；不留下灰色废话；
   - 未选场景时显示简洁说明和一个“添加场景”动作；不显示空白的永久右栏；
   - 当前结果优先展示实际视频播放器。运行历史折叠为紧凑时间列表，成功记录可设为当前，运行中可取消；
   - 删除继续使用确认，不允许一击删除场景。

### 3.3 项目级设置

项目默认视频模型不是与场景创作同等重要的表单字段。它位于项目栏的“默认模型”紧凑选择器：

- 已选时显示供应商显示名和模型名；
- 未选时文案为“每个场景单独选择”；
- 场景单独模型优先于项目默认模型；
- 没有可运行视频模型时，显示“配置视频模型”并直达模型工作台的 video filter。

## 4. 生成前的安全与状态模型

### 4.1 场景准备度

生产台的场景状态由真实数据推导，不新增持久状态：

| 状态 | 条件 | 画布/列表表现 | 可执行动作 |
| --- | --- | --- | --- |
| 待完善 | 缺少提示词或可运行模型 | 中性提示 | 编辑场景 |
| 可生成 | 提示词、模型、比例、时长都满足当前 Adapter 能力 | 可生成标识 | 生成此场景 |
| 生成中 | 最新关联任务处于 queued/running/approval | 运行中标识 | 查看任务/取消 |
| 需处理 | 最新任务失败、取消或无可用产物 | 警告标识 | 查看原因/重新生成 |
| 已选结果 | `selectedMediaSceneRunId` 对应成功视频 | 成功标识 | 播放/更换当前结果 |

后端在创建场景运行前仍是唯一的最终校验方。前端准备度只用于解释和防止无意义的点击，不能绕过 Provider capability、工作区素材边界或 API Key 校验。

### 4.2 批量生成确认

“按顺序生成”先打开确认面板，而非直接发送请求：

- 显示“将提交 N 个场景”，按顺序列出可运行场景；
- 缺少提示词、模型或处于运行中的场景列为“本次不提交”，给出可理解原因；
- 没有可运行场景时，主按钮不可用，唯一主动作是定位第一个待完善场景；
- 确认按钮文案是“生成 N 个场景”，不暗示合成最终成片；
- 服务器只接收确认过的 scene id，并在所有入选场景通过最终校验后再创建任务，避免旧实现中前几个场景已创建、后一个出错造成的半提交。

生成已提交后，场景状态即时变为“生成中”；任务页和场景历史都可看到同一条任务。保存项目、编辑其他场景、移动节点或切换 tab 不触发生成。

## 5. 生成任务体验

任务页是任务与结果的回看台，不应重复占用一个完整页面级 Header。

- 嵌入媒体生产时使用紧凑工具栏：任务状态筛选、简短数量摘要、刷新、创建生成任务；
- 列表优先显示真实结果缩略图/视频首帧、任务类型、模型、更新时间和状态；提示词只显示一行摘要；
- 成功的视频不显示通用图片占位。详情中用 `<video controls preload="metadata">` 内联播放；浏览器无法播放时保留“打开结果”和“下载”回退；
- 图片继续使用图片预览；非媒体 artifact 不占结果首屏；
- 任务详情首屏按“结果 -> 主要动作 -> 提示词 -> 参数”排列，Provider ID、Job ID、原始错误只在“技术详情”展开区；
- 状态文案统一为中文产品语言：待生成、生成中、需要处理、已完成。模型名和供应商专有名可保留。

### 5.1 新建生成任务

创建对话框按操作收敛字段：

- 选择“视频生成”后，模型、提示词、画幅比例和时长属于主表单；水印进入“更多设置”；
- 只有可真实运行的模型可被选择；选择模型后，比例和时长仅展示该模型真实声明的选项；
- 提交按钮说明“创建任务”，不是“开始生成”。任务创建和实际运行保持现有两阶段语义；
- 对话框不展示 JSON、Provider ID、Adapter、metadata 等实现词。

## 6. 视觉和交互原则

- 延续频道设置与模型工作台的紧凑、清晰的行/面板语言：1px 边框、最多 8px 圆角、浅色选中背景加左侧黑色标识；
- 普通信息不使用灰色厚底。灰底只表达选中、禁用、等待或空态；
- 一页只允许一个明确主动作：场景选中时是“生成此场景”，项目级确认后是“生成 N 个场景”，任务页是“创建生成任务”；
- 用图标按钮承载刷新、上移、下移、复制、删除，并提供 title/aria-label；文字按钮只用于清晰命令；
- 分镜画布的缩放控件仅在至少两个场景时出现，缩略地图仅在五个及以上场景时出现；单场景不为将来可能的复杂度占用注意力；
- hover、keyboard focus 和 disabled 状态都不能造成布局变化；
- 成功短提示 2 秒后消失；保存失败、生成失败、删除确认和缺少模型提示保持可见直到用户处理。

## 7. 模块与安全边界

| 模块 | 职责 | 禁止承担 |
| --- | --- | --- |
| `MediaProductionWorkspace` | 页头、tab、三栏装配 | API 调用和复杂场景派生 |
| `use-media-production-controller` | 项目/场景请求、副作用、局部忙碌状态 | JSX 和视觉派生 |
| `media-production-view-models` | 场景准备度、运行摘要、批量确认内容 | API 调用、React state |
| `SceneOutline` | 场景序列和明确排序操作 | Provider 请求 |
| `SceneInspector` / `SceneRunHistory` | 编辑、结果预览、历史选择 | 项目级副作用 |
| `MediaArtifactPreview` | 图片/视频结果播放与回退 | Job 状态判断、数据加载 |

任何生产源文件保持在 800 行以下。媒体密钥、Authorization、外部任务句柄和原始 Provider 响应不能进入 UI props、截图、诊断默认层或浏览器日志。

## 8. 验收标准

- 1440x1000、1280x800 中文白天模式：页面壳不滚动，场景列表、画布、检查器和任务列表各自内部滚动；
- 项目名称只出现一个可编辑入口；有 5 个以上场景时仍能看清顺序和选择状态；
- 视频任务成功后，列表和详情都展示真实视频媒体，而不是通用文件/图片占位；
- 批量确认只提交准备好的场景，后端不会因后续无效场景留下半提交任务；
- 未配置或无法运行模型、空项目、空提示词、运行中、失败、完成、删除确认、视频播放失败等状态都有明确下一步；
- 任务页不再出现两个大标题和重复主按钮；
- 原有独立任务、场景运行、结果选用、取消、重试、媒体适配器和模型工作台路由保持兼容。
