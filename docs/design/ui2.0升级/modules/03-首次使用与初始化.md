# 首次使用与初始化

## Goal

首次使用只引导用户完成可运行 workspace、provider/model 和初始化检查，不解释内部模块。
流程必须告诉用户当前步骤、失败位置和修复行动。

## Function Points

- `FIRST-WORKSPACE-001`：选择/确认 workspace。
- `FIRST-PROVIDER-001`：选择 provider、模型和 API Key。
- `FIRST-CHECK-001`：配置检查与失败修复。
- `FIRST-PROGRESS-001`：步骤进度、返回和重试。
- `FIRST-COMPLETE-001`：完成并进入可工作的页面。

## Structure

使用单一 Dialog/全页流程：步骤标题、必要字段、当前检查摘要、单 primary CTA。Advanced 和
raw error 默认折叠。步骤切换不改变容器尺寸，失败停留在当前步骤。

## States

workspace missing/invalid、provider loading、model empty、API key missing、check running、
check failed、partial ready、complete。Ling Agent 可用后才能完成；非阻塞可选项不阻止。

## Components

Dialog、Field、Select、Button、StatusIndicator、InlineFeedback、Progress/Skeleton。禁止使用
多个彩色步骤卡片。

## Current Reachability Audit

截至 2026-07-20，仓库中的 `features/workspace/FirstRunFlow.tsx` 只从 workspace barrel 导出，没有生产
import 或可达入口；当前 13 个 `ViewId` 也没有 onboarding/first-run view，`AppShell` 没有首次启动 gate，
E2E 没有真实 workspace/provider/check/complete 流程。它是旧的“provider -> channel -> task -> run”面板
实现，不能作为当前首次启动体验已经存在的证据，也不应先做视觉迁移。CLI 注入默认 cwd 只提供 workspace
默认值，不等于完成标记、跳过语义或恢复协议。

进入实现前必须先完成一个独立接入切片：

1. 确认 Desktop/Web 第一次启动的权威触发条件和完成标记；
2. 确定完成标记的所有者、存储位置、版本、Web/Desktop 同步和升级重置策略；
3. 明确返回、跳过、中断关闭、刷新、断线、检查失败、部分完成和再次进入后的恢复语义；
4. 决定复用旧状态派生、重建单一 Dialog/全页流程，或删除旧文件；
5. 把真实入口、恢复、完成后目标页面和跨主题状态加入 `app.spec.ts` 与 Desktop 验收；
6. 入口可达后再迁 Dialog/Field/Button/Status，不为死代码建立第二套 UI。

P4.9 首先是产品接入决策，不是视觉切片。用户确认前只允许做 reachability/inventory 审计和设计补充；
不得自行写入临时 `localStorage` 完成标记，或把旧 channel/task/run 流程默认为新 IA。若产品决定暂缓，
本模块保持 `inventory`，执行指针可转到 P7A Settings，不阻塞已批准的纯展示迁移。

因此全部 `FIRST-*` Function ID 继续保持 `inventory`。

## Tests

`app.spec.ts`。验证键盘、返回不丢字段、失败修复、完成后目标页面和两个内置 Theme Pack。
