# 频道工作区

> 2026-07-30 模型归属更新：新建频道必须选择已检查可运行的 `Ling Agent 模型`，工作区默认仅负责预选，
> 创建后保存为频道专属的 Ling Agent 模型。其他队友继续使用工作区默认或自身固定模型；完整合同见
> [`conversation-model-binding-and-creation-validation.md`](../../conversation-model-binding-and-creation-validation.md)。

## Goal

频道是 Ling 最完整的协作工作面，也是普通对话和私聊的交互基准。业务能力不减少，UI 2.0
统一 Header、Feed、Composer、Summary、Terminal、Right Dock 和深层工作区。

## Function Points

- `CHANNEL-HEADER-001`：标题、成员栈、刷新、摘要、终端、详情和频道专属入口。
- `CHANNEL-SEARCH-001`：消息/附件/运行关联搜索。
- `CHANNEL-SUMMARY-001`：环境和上下文摘要 Popover。
- `CHANNEL-TERMINAL-001`：底部终端、关闭和高度拖动。
- `CHANNEL-DOCK-001`：Review/Evidence/Files/Context 和宽度拖动。
- `CHANNEL-FEED-001`：消息、流式内容、工具、审批、Artifacts。
- `CHANNEL-COMPOSER-001`：输入、权限、mentions、附件、发送、停止。
- `CHANNEL-TASK-001`：频道右侧栏内的任务创建、任务详情、权限和运行行动。workflow proposal 与
  thread replies 的消息呈现归 `CHANNEL-FEED-001`；独立 Work Board 归 `modules/14-Work-Board.md`。
- `CHANNEL-ENV-001`：环境、Git 状态、提交、工作流转换。
- `CHANNEL-SETTINGS-001`：General、Workspace、Collaboration、Health、Governance。
- `CHANNEL-OVERLAY-001`：创建、重命名、提交、预览和治理通知。
- `DESKTOP-CUA-CONTROL-001`：Desktop current-session Computer Use 状态、Show/Hide 和 Stop。

## Layout

Header 高度稳定；Search 展开不顶出边框。消息列和 Composer 使用统一 conversation width。
Summary、Dock、Terminal 状态独立，打开 Dock 时 Summary 平滑移位。Dock/Terminal 使用共享
resize controller 和 min/max token。

## Action Hierarchy

顶部主工具 icon-only；频道成员和治理保留专属 slot。Review/Evidence/Files 不回到顶部。
离开频道的行动明确标注，行点击不隐式切壳。

Desktop capability 通过 Header 固定 slot 接入，不改变 Web toolbar 顺序。存在当前 Computer Use
会话时显示状态和 `32x32` icon actions；不存在时整个 slot 隐藏但不留下空白。命令失败显示在
锚定反馈层中，不能把 Header 或消息列向下推。Show/Hide 只控制 PiP；Stop 是独立 danger action。

## States

空频道、加载历史、流式、排队、等待审批、工具失败、断线、无 cwd、无任务、Git dirty、
冲突和成功。技术事件进入 WorkCell/Details，不直接铺满消息流。

## Current And Target

当前 `WorkspaceClientView.tsx` 超大，只允许接入抽出的 UI 组件。目标使用 PageHeader、
IconButton、Popover、Drawer、Tabs、Dialog、Conversation UI、InlineFeedback。

## Tests

`channel.spec.ts`、`workspace.spec.ts`、`composer-token.spec.ts`、`dark-mode.spec.ts`。覆盖
工具顺序、summary/dock 动画、拖动、终端、所有设置 Tab 和 overlays。Desktop 另由
`desktop-computer-use-bridge.spec.ts` 覆盖 slot、Header 稳定性和 Show/Hide/Stop 语义。

## Migration Checkpoint

P5.2 已验证 `CHANNEL-SUMMARY-001` 和 `CHANNEL-TERMINAL-001`；`CHANNEL-DOCK-001` 的共享
open/close/resize/motion 已实现，深层 launcher/page 状态仍由 P6A 关闭。Header、Search、Feed、
Composer、Task、Environment、Settings 和 Overlay 不随共享面板切片提前完成。

证据：[Shared Conversation Panels](../evidence/conversations/shared-panels/metadata.md)。

### P6A.1 Header And Search（verified，2026-07-19）

- 普通频道工具条顺序已经收敛为 `Search / Refresh / channel-specific slots / Summary / Terminal / Details`；
  Settings 和 Environment 专用 Header 不伪造普通频道能力。
- Search 与 Refresh 使用 P5 package-owned icon-only Toolbar primitive；成员头像栈和治理 slot 保持频道专属。
- Header Search 复用 Activity controller，覆盖消息正文、file ref、附件文件名/路径、任务和运行标题；
  没有新增后端 API 或第二套查询状态。
- Clear 保持 Search 打开并恢复焦点；Esc、重复点击 Search、切换频道时关闭并清空，避免隐藏过滤条件。
- Header Search 打开时隐藏 Activity tools 内的重复搜索字段；Activity 高级筛选仍可独立打开。
- Refresh await 现有 AppShell 刷新链，只有 Refresh button 进入 loading，Toolbar 和其他 action 不 busy。
- `channel-header.css` 接管 Header/Search focused layout；搜索 focus 不改变 48px Header 高度，长标题和三名成员
  在 `1440x960` Light、`1280x800` Dark 下无重叠或横向溢出。

证据：[Channel Header And Search](../evidence/conversations/channel-header-search/metadata.md)。

下一切片是 `CHANNEL-FEED-001 + CHANNEL-COMPOSER-001`。Task、Environment、Settings、Overlay 和

### P6A.2 Feed And Composer（verified，2026-07-19）

本切片只迁移频道默认对话面的 Feed 与 Composer，不改消息 API、workflow/turn 投影、权限策略、
上传协议、运行状态机或频道 IA。

Feed 合同：

- `.message-feed` 是频道聊天区唯一纵向滚动 owner；Composer、Header、Right Dock 和 Bottom Panel
  不随消息滚动。
- 消息列、虚拟行和 Composer 共用 `--channel-conversation-width`，在 `1440x960` 与 `1280x800`
  下左右边界一致；页面本身不得产生横向滚动。
- loading、empty、no-result、streaming、approval、failed、pending-send、history pagination 和
  jump-to-latest 都属于验收状态。用户阅读旧消息时，流式增长不能抢回滚动位置。
- primary active stream 与 multi-agent detail stream 使用不同语义标记。多队友详情不能被测试、
  可访问性树或 CSS 识别为多个顶层主活动流。
- 技术诊断继续进入 WorkCell/Details；普通消息流不新增 raw provider、route、trace 或 transport 文案。

Composer 合同：

- 频道继续复用 package-owned `ConversationComposerShell`、`TokenizedComposerInput` 和权限菜单；
  feature 只提供频道状态、业务 callback、附件/mention/goal/plan slots。
- 权限菜单由共享 Radix Menu 管理 open、keyboard、Esc、outside dismiss 和 focus restore，频道不得
  保留 document-level pointer/key listener。
- 输入 focus 不改变 Composer 外部高度或列宽；附件、mention、slash、URL 和 workspace file token
  稳定换行，长内容只在输入 owner 内滚动。
- send、stop、queued、sending、stopping、failed、disabled 都使用真实状态。失败必须保留草稿并提供
  Retry/Dismiss；短成功反馈自动清除，不进入 Feed。
- Feed/Composer 的 loading、failure 和 jump-to-latest 控件优先使用 `@ling-stack/ui-react` primitive；
  保留必要旧 class 仅用于兼容测试和当前 CSS 删除切片。

实施边界：

- `WorkspaceClientView.tsx` 只接入 `ChannelFeedChrome` 等纯展示节点，不新增 Feed/Composer 状态机。
- `ChannelComposer.tsx` 只组合 slots；反馈块抽为 focused component，权限交互留在共享 package。
- `ChannelMessageFeed.tsx` 保留虚拟化、anchor restore 和 history pagination；新投影不得复制这些逻辑。
- 新样式进入 package-owned Composer CSS 或 `channel-feed-composer.css`，不向 `components.css`、
  `layout.css`、`strict-console.css` 追加规则。

验证结果：

- `ChannelFeedChrome` 和 `ChannelComposerFeedback` 承担 focused 展示，超大 Workspace 文件只接线；
- 顶层 active stream 与队友详情 stream 使用独立语义标记，既有 multi-agent 基线已修复并专项通过；
- package-owned Composer CSS、Radix permission Menu 和 focused `channel-feed-composer.css` 已接入，
  对应 legacy family 从 `components.css` 迁出；
- package tests 为 `40/40` 与 `10/10`，focused `3/3`、App/Composer/Dark/Toolbar/Panel `32/32`、
  完整 Channel `105/105`、完整 Teammates `21/21`；
- `1440x960` Light、`1280x800` Dark 和 Composer failure 三张 changed-state 截图已原尺寸目检，
  无 document overflow、菜单裁切、主题串色或页面级重复错误。

证据：[Channel Feed And Composer](../evidence/conversations/channel-feed-composer/metadata.md)。

`CHANNEL-FEED-001` 与 `CHANNEL-COMPOSER-001` 进入 `verified`。下一切片是
`CHANNEL-TASK-001 + CHANNEL-ENV-001`；Settings、Overlay 和 Dock 深层页面继续保持 open。

### P6A.3 Task And Environment（verified，2026-07-19）

本切片按生产可达面重新校准所有权：频道任务实际入口是 Right Dock 内的创建面与详情面；
`ChannelTaskWorkspace.tsx` 没有生产调用，已删除，避免维护第二套不可达任务 UI。workflow proposal、
thread reply 和 WorkCell 继续由已经验证的 Feed/Composer owner 承担，不在任务面复制。

任务合同：

- `NewTaskPanel` 与 `TaskDetailPanel` 已拆为 focused 展示组件，`WorkspaceClientView.tsx` 只保留状态和
  callback 接线；任务主状态由 `channel-task-view-models.ts` 按
  `blocked > waiting > failed > running > queued > complete > ready` 派生。
- 创建面使用共享 Field/Input/Textarea/Select/Button；工具与 generation-only 说明进入默认折叠的
  Execution context，不在首层形成说明墙。
- 详情面使用共享 StatusIndicator、DataRow、InspectorSection、SegmentedControl 和 InlineFeedback；
  Task context 与 Permissions 默认折叠，四个权限预设在窄 Dock 中使用可见的 `2 x 2` 布局。
- 行动 loading 只属于触发按钮；failed/blocked/waiting 持续反馈保留修复行动。任务详情是唯一滚动
  owner，sticky action footer 不扩大页面或产生横向滚动。

环境合同：

- Environment 是独立 utility page，默认层固定为五行：workspace、changes、review、branch、commit；
  path、变更总数、staged/unstaged/untracked/conflicted、diff stat 和唯一主状态 data-first 展示。
- Git transport error、workspace missing 和 conflict 使用持久 InlineFeedback/StatusIndicator；clean、
  not-repo、review-only 和 loading 不伪造成功或变更状态。
- Browser/Sources/Output 进入默认折叠的 Evidence and output Inspector，不把 raw evidence 铺在首层。
- Commit/Push 仍是现有只读预览，不新增 Git API；手写 overlay 已迁共享 Radix Dialog，单次 Esc 关闭、
  焦点恢复 Open trigger，四个动作在小弹窗中使用 `2 x 2` 布局且无文字截断。

实现与验证：

- 新增 focused `channel-task-environment.css` 与 `channel-workflow-preview.css`；workflow preview 同步迁到
  shared Dialog，避免删除旧 Environment backdrop 后留下无样式可达弹窗。`components.css`
  `15,801 -> 14,998`、`layout.css` `1,920 -> 1,894`、`runs.css` 删除 341 行不可达任务 selector、
  `workspace.css` 删除 51 行旧反馈样式。
- Web typecheck、i18n、UI2 lint 通过；focused `5/5`；Workspace/Dark/P5/P6A 联合回归 `30/30`；
  Channel 全量首跑 `104/105`，唯一旧 selector 修正后目标 `1/1`，workflow 迁移后目标 `2/2`，
  其余 104 项没有回退。
- 六张真实 Vite 证据覆盖 1440 Light task detail/workflow preview/conflict/commit preview 和 1280 Dark
  new task/Git unavailable；截图等待 Dock 实际 layout width 到达 304px 后采集，全部原尺寸目检。

证据：[Channel Task And Environment](../evidence/conversations/channel-task-environment/metadata.md)。

`CHANNEL-TASK-001` 与 `CHANNEL-ENV-001` 进入 `verified`。下一切片是
`CHANNEL-SETTINGS-001 + CHANNEL-OVERLAY-001`，并在 Right Dock 深层 launcher/page 完成后再将

### P6A.4 Settings, Overlay And Dock（verified，2026-07-19）

Settings 合同：

- 标题旁 `More channel views` 是频道设置的常驻入口；模型健康与否不影响入口可达性。
- General 中只切换一个“Ling Agent 模型”。Members 只读显示 `Ling Agent 模型 / 工作区默认 / 固定模型`，
  不在频道内改写其他队友的全局模型绑定。
- General、Workspace、Members、Councils、Health 使用同一个共享 Tabs owner；keyboard Home/End、唯一
  active panel、内部滚动和长标签 containment 已验证。
- General 覆盖 invalid/save failed，Workspace 覆盖 scoped refresh busy，Members/Councils 覆盖 empty，
  Health 覆盖 loading/error；局部行动不会让整个 Settings 页面进入 busy。
- utility header 与 Environment 共用 `channel-header.css`，Settings 主网格和五个 panel 归
  `channel-settings.css`。共享 Field/Button/DataRow/Feedback 视觉不在 Feature 重定义。

Overlay 合同：

- Rename 使用共享 Dialog，初始焦点进入名称字段，单次 Esc 关闭并把焦点恢复到
  `More channel views`；失败反馈留在 Dialog。
- Governance 使用共享 modal Popover，Esc/outside dismiss/focus restore 由 Radix owner；Feature 不恢复
  document-level listener。
- Approval/context detail 是 Feed 内 Inspector，不生成第二个全局 Dialog 或 scrim。
- Create、Commit 和 Workflow Dialog 保持既有业务和 P6A.3 owner，本切片只做联合回归。

Dock 合同：

- launcher、page header、Back、Close、EmptyState 和通用 list 归 conversation package；Channel adapter
  只提供 review、plan、file、activity、browser 和 terminal 数据投影与 callback。
- 每个可达 launcher 均覆盖 loaded/failure/detail，Review 覆盖长 diff，Plans 覆盖 lineage、Back 和
  resize；loading/error/selected detail 不改变 Dock 外宽。
- Dock 等待稳定宽度后截图，拖动继续使用共享 controller/pointer capture/clamp，不新增 resize state。
- domain CSS 分到 `channel-right-dock/plans.css`、`review-details.css` 和 `workspace-changes.css`；
  `components.css` 不再拥有 Settings/Dock 重复 selector。

验证结果：

- `@ling-stack/ui-react 40/40`、`@ling-stack/conversation-ui-react 10/10`、focused `7/7`；
- owner-only CSS 收口前最终联合 E2E `144/144`；收口后 typecheck、i18n、lint、diff check 和 focused
  `7/7` 重跑通过；
- 12 张真实 Vite 证据覆盖 7 张 `1440x960 ling-light` 和 5 张 `1280x800 ling-dark`；原尺寸检查无
  document overflow、主题串色、重叠、截断行动或动画中间态；
- `components.css` `11,457 -> 11,388`，Web CSS `46,020 -> 46,017`，focused CSS 禁止项均为 `0`。

证据：[Channel Settings, Overlay And Dock](../evidence/conversations/channel-settings-overlay-dock/metadata.md)。

`CHANNEL-SETTINGS-001`、`CHANNEL-OVERLAY-001` 与 `CHANNEL-DOCK-001` 进入 `verified`。Channel P6A
全部关闭；下一切片进入 `P6B Normal Conversation`，以本频道结构和证据作为视觉、交互与状态基准。
