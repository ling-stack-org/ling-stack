## Shared Boundary

三个页面共享紧凑列表、状态、筛选、详情 Inspector 和 scoped feedback，但不共享领域状态机。
UI 只投影 daemon 权威数据，不根据时间、日志文本或本地请求猜测成功、失败或审批结果。

## Automations

- 列表显示名称、计划、下次运行、最近结果和启用状态；正常项不堆积健康标签。
- 创建/编辑使用结构化 schedule 控件，不要求用户编写 RRULE；原始表达进入技术详情。
- 启停、立即运行、编辑和删除各自拥有 busy/error。刷新保留现有列表，旧请求不能覆盖新状态。
- 删除使用明确影响的 Dialog；自动化运行继续出现在标准 Runs 中。

## Runs And Threads

- Runs 是执行事实，Threads 是会话事实；关联可以导航，但不能合并成一个生命周期。
- 列表突出对象、状态、开始时间和需要用户处理的行动；provider ID、raw tool payload 和内部 route 折叠。
- running、waiting、approval、failed、cancelled、completed 使用唯一主状态；partial/stale 不冒充 completed。
- Cancel、retry 和 intervention 只在 API 真正允许时出现，操作失败保留原权威状态。
- 长输出、事件和技术 metadata 在详情内部滚动，不撑开页面。

## Approvals

- 待处理审批优先显示请求主体、风险、范围和允许的选择；已决定记录只读。
- Approve/Deny/Ask 使用真实策略能力，不增加第三套前端审批规则。
- mutation 期间锁定同一审批的重复行动；失败保留请求和用户输入，成功以后端状态为准。
- 高风险影响必须持续可见，不能依赖 Tooltip、hover 或颜色；秘密和无关 raw payload 不进入默认 UI。
