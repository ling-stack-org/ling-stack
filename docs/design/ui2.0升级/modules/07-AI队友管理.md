## Goal

将队友列表、创建和详情 Tabs 收敛为管理工作台。默认层显示身份、状态、模型 readiness 和
主行动；技术绑定和诊断进入对应 Tab/Inspector。

## Function Points

- `TEAMMATE-LIST-001`：搜索、筛选、选择、hidden 和空态。
- `TEAMMATE-CREATE-001`：预设/自定义切换、全屏创建页、头像、模型、描述和创建进度。
- `TEAMMATE-PROFILE-001`：身份、头像上传/裁剪、简介和状态。
- `TEAMMATE-MODEL-001`：模型选择、缺少 Key 和检查反馈。
- `TEAMMATE-SKILLS-001`：技能搜索、筛选、当前队友绑定开关和按需详情；导入、归档和来源治理归技能库。
- `TEAMMATE-MCP-001`：MCP server/tool 授权条件嵌入“工具与权限”，未配置 Server 时不显示空区块。
- `TEAMMATE-MEMORY-001`：设置页已撤销；当前私聊已使用的记忆摘要继续由右侧详情投影。
- `TEAMMATE-CHANNELS-001`：频道成员关系和默认频道。
- `TEAMMATE-TASKS-001`：设置页已撤销；仅保留私聊消息转任务和既有 Work Board/Run 业务能力。
- `TEAMMATE-PERMISSIONS-001`：编辑当前队友能力上限与额外确认强度，并显示不可突破的工作区限制。
- `TEAMMATE-ACTIVITY-001`：设置页已撤销；私聊右侧详情继续显示上下文活动投影。
- `TEAMMATE-DANGER-001`：停用和永久删除进入资料页底部“管理队友”，受保护队友隐藏。

## Layout

列表 + 详情工作区，详情 Tabs 稳定。创建自定义队友使用铺满 Dialog 的独立页，左上返回，
头像和模型为必要字段；创建过程显示真实步骤，成功后关闭整个创建 Dialog。

## Action Hierarchy

列表行为选择，主行动为创建或修复。资料、模型和工具与权限由 Header 拥有当前分区的保存行动；
技能绑定和 MCP 授权保留各自的即时/局部保存语义。不可配置的工作区规则只作为上限展示，正常状态不提供跳转；
只有实际被工作区拒绝时显示“去处理”。

## States

loading、empty、hidden、protected system teammate、missing model、upload/crop、creating、
step failed、success、save error、delete blocked。

## Components And Tests

DataRow、Tabs、Dialog、Field、Select、Progress、StatusIndicator、InlineFeedback、Toast。

## 2026-07-30 私聊设置收口

- 私聊标题旁常驻 More 菜单，顺序为 `设置 / 重命名队友 / 上下文`。`设置` 默认进入资料页；模型正常后入口仍然存在。

## 2026-07-31 核心导航与默认层减噪

- 普通可编辑队友的设置导航固定为 `资料 / 模型 / 频道 / 技能 / 工具与权限`。工具与权限是单队友能力入口，
  不能因为没有 MCP 或当前没有异常而隐藏；Ling Agent 等受保护队友按能力隐藏不可编辑入口。
- `工具与权限` 只修改当前队友的 `allowedTools`、额外审批强度和 MCP 授权。工作区默认授权、沙盒、网络和
  allow/ask/deny 仍由 Settings 管理，并始终是不可突破的上限；只有工作区阻止当前能力时才提供“去处理”。
- MCP 在用户默认层统一称为“外部工具”。没有已配置服务时不显示该区块；有服务时只展示服务名称、可用性、
  已允许功能数和“管理”。服务连接、密钥、同步和删除仍由全局设置负责，队友页只决定当前队友可使用哪些
  已连接功能。
- 具体外部功能进入右侧管理抽屉，使用名称、说明、风险语义和复选框。默认层与抽屉均不显示 MCP、server id、
  raw tool name、transport、密钥状态或“全选当前 MCP”等实现术语；连接异常只显示可理解的处理状态。
- 服务返回的动态说明如果包含 MCP、server id、transport、stdio 等接入术语，则在队友页省略该说明，搜索也
  不匹配被省略的技术文本；原始服务定义保持不变，仍由全局 MCP 工具服务页负责诊断。
- 抽屉中的功能列表按内容自然撑开，仅在超过抽屉可用高度时内部滚动；少量功能不得制造撑满整屏的空白边框。
- 外部工具修改与普通能力共用页面顶部“保存修改 / 重置”，内容区不再有第二个保存按钮。关闭抽屉只保留
  当前草稿，不自动授权或保存；新发现的服务功能不会自动加入当前队友权限。
- 权限正常层只使用“可用能力 / 默认执行范围”：能力可编辑，工作区默认范围只读。raw 工具 ID、required
  actions 和完整 allow/ask/deny 决策明细不在队友设置展示；删除重复标题、技术信息、健康状态、逐项灰色
  说明和常驻跨页按钮。
- `记忆` 暂时退出设置导航。当前工作区健康、治理和复核收件箱不伪装成单队友配置；私聊右侧详情保留记忆
  摘要，待支持查看、编辑和遗忘当前队友的具体记忆后再恢复独立页。
- `危险操作` 退出导航，停用与删除进入资料页底部“管理队友”；受保护队友不显示不可执行的危险操作。
- 技能页只管理绑定，默认结构为 `搜索 / 筛选 / 技能 + 说明 + 使用开关`。开关即时绑定、启用或停用；导入、
  高级 Skill ID、归档和来源治理回到技能库。正常技能不显示状态，缺失、阻断或来源异常才显示“需处理”。
- 技能列表使用内容自然高度，不设置固定高度或视觉最小高度。列表 viewport 的 `max-height` 必须扣除私聊设置
  Header、页签、内容边距、搜索栏和表头；只有技能超出剩余空间时才由列表内部滚动，不得再撑出外层设置页滚动条。
- 技能详情默认只展示名称、说明、当前队友是否使用和异常阻断；工具与确认规则折叠，来源和 raw 技术字段
  放入“技术信息”。搜索只匹配名称、说明和用户可见工具名称。
- 灰色辅助文案只在能消除歧义、说明不可逆后果或帮助修复异常时出现。正常、健康、只读状态保持静默。
- 下文 P8.1e/P8.1g/P8.1j/P8.1l 记录历史完成证据；其旧导航、只读权限页、工作区记忆页和危险操作独立页
  不再代表当前可达信息架构。

### 资料页布局收口

- 普通队友默认层按 `头像与名称 / 简介 / 状态与侧栏显示 / 高级资料 / 管理队友` 排列。简介位于状态之前，
  不让运行状态和低频侧栏设置抢占身份信息的视觉层级。
- 名称行不再重复显示状态点。头像操作由头像上的单一菜单入口承载，更换头像和恢复默认头像不再出现在
  名称输入框尾部，也不得呈现为“删除队友”。
- `固定在侧边栏` 与 `从侧边栏隐藏` 合并为一个 `侧栏显示` Select：`固定显示 / 正常显示 / 隐藏`。选择
  任一状态会产生互斥的 `pinned/hidden` 组合，不新增存储字段或迁移。
- `高级资料` 默认折叠，只保留系统提示词和一个“导入角色设定”入口。人格导入进入独立 Dialog，输入模式
  为 `选择文件 / 粘贴内容`；选择文件只展示文件名，不展示或允许编辑本地绝对路径。
- 人格导入操作文案使用 `检查内容 / 应用到资料`。修改文件或粘贴内容后旧预览立即失效；应用失败保留
  输入和预览，成功后关闭 Dialog 并沿用现有全局 Toast。
- 资料列宽使用约 `880px` 的桌面上限，减少纵向间距，不增加卡片嵌套或视觉最小高度。页面内容不足时
  自然撑开，超出 Settings 可用区域时继续由现有内容滚动层负责。
- Ling Agent 继续只显示允许编辑的名称、头像、简介和附加指令，不获得普通队友的状态、侧栏显示、系统
  提示词、人格导入或管理入口。

`teammates.spec.ts` 和 `ling-light` / `ling-dark` 覆盖所有 Tabs、创建步骤、头像、危险操作和长列表。

## P8.1 List And Search Contract

`TEAMMATE-LIST-001` 的首个实施切片只迁移管理列表，不重做已经验证的创建流程或私聊工作区。

页面默认层按以下顺序组织：

```text
Workspace teammates
  compact count + refresh
  search + status filter
  optional scoped load feedback
  bounded teammate list
    identity | model/channel/time summary | one primary status | actions
  compact empty/no-result state
```

硬规则：

- 搜索匹配名称、简介、角色、模型和频道；搜索不改变服务端数据，也不写持久化。
- 状态筛选固定为全部、就绪、需配置模型、已隐藏；disabled/archived 对象继续不进入当前列表。
- 每行只显示一个主状态：`需配置模型` 优先于 `已隐藏`，其余为 `就绪`。隐藏是筛选维度和弱化表现，
  不伪装成运行失败。
- model、channel 和更新时间是紧凑摘要；raw provider ID、channel ID、system prompt 和权限细节不在列表展示。
- 日常主行动为打开私聊或配置模型；Pin、Hide、Delete 进入共享 Menu。Menu 使用 Radix 的 Esc、外部点击、
  roving focus 和 trigger focus restore，不再监听 `document`。
- loading 且没有权威数据时显示稳定 Skeleton；背景刷新保留旧列表，只让 Refresh 显示 busy。
- 刷新失败保留最后成功列表并显示持久 InlineFeedback；成功刷新清除该反馈。
- 空列表提供一个 `New AI teammate` 行动；搜索/筛选无结果提供清除条件，不伪装成没有队友。
- 列表是唯一纵向滚动 owner；`1440x960`、`1280x800` 和 Settings 嵌入态均不得产生文档横向滚动。
- 行使用 shared `DataRow`、`StatusIndicator`、`Button/IconButton`、`Menu`；搜索和筛选使用 shared
  `Input/Select`。Feature 不直接导入 Radix，也不覆盖 `.ling-ui-*` 内部 selector。

### Reachable State Matrix

| State | Trigger | Required result |
|---|---|---|
| initial loading | first teammate request pending | stable skeleton rows, no false empty state |
| loaded | list request succeeds | searchable rows, one status and bounded actions |
| background refresh | rows exist and Refresh runs | rows remain visible, only Refresh is busy |
| refresh failure | list request rejects | old rows remain, persistent scoped feedback appears |
| empty | loaded list has no active teammate | one compact empty state and create action |
| no result | query/filter excludes all rows | no-result state and clear filters action |
| hidden | hidden filter or hidden row in All | row remains reachable and visually secondary |
| needs model | provider absent or preflight not ready | warning status and Configure model primary action |
| long content | long name/model/channel labels | ellipsis/title, no action collision or overflow |
| menu open | More action | Portal menu, keyboard navigation, one Esc close and focus restore |

## P8.1b Default Roles And Create Contract

`TEAMMATE-CREATE-001` 以现有真实创建链路为业务基准，只升级默认角色与创建 Dialog：

- Default roles 是中性紧凑列表，整行打开角色详情；不再使用卡片墙、伪 `View` 文案或主题硬编码颜色。
- 创建 Dialog 固定为 `Header / one scrolling Body / Footer`；角色选择、自定义设置和真实进度是三个互斥状态。
- 顶层只显示角色、名称、频道和已就绪模型；系统提示、raw capability、provider route 和高级记忆字段不进入创建默认层。
- 自定义设置保留返回、头像上传/移除、色板、名称、模型、简介和频道；上传仅本地预览，创建时才进入现有上传流程。
- 七步创建进度由现有事件驱动；模型失败停留并提供返回设置/模型工作台，成功关闭整个 Dialog 并打开私聊。
- 队友记录已创建但头像、频道、记忆或刷新失败时，显示“已创建但有设置警告”，保留失败步骤并直接打开
  已创建队友；不得返回设置后重复创建第二条队友记录。
- 创建中不可关闭；编辑和失败态支持 Esc、外部点击和触发点焦点恢复。
- Dialog、Field、Input、Textarea、Select、Button、IconButton、EmptyState、Spinner 和状态反馈全部来自 shared UI。

状态矩阵、组件拆分、CSS 删除范围、focused E2E 和截图证据见 implementation plan 第 10 节。

## P8.1c Settings Shell And Profile/Avatar Contract

`TEAMMATE-PROFILE-001` 复用现有资料、头像和 persona API，只迁移当前真实可达的单队友设置面：

- Settings Header 只显示返回、队友设置标题和当前 Tab 的主行动；Profile 使用唯一 Reset/Save，Profile

- 普通队友的 System prompt 与 Persona import 进入默认折叠的 `InspectorSection`；persona 仍先 Preview draft，

- 成功反馈进入唯一全局 Toast 并自动消失；保存、头像、persona 失败留在 Profile 内的 `InlineFeedback`，

- Profile Reset 只恢复当前队友的可编辑资料草稿；保存/头像/persona 的 busy 状态彼此独立。
- 右侧 Configuration summary 只保留可扫描数据，删除常驻 Import guidance 说明；它不拥有保存或诊断行为。

Settings shell/header/navigation 是本切片的共享支撑面；后续 Model/Skills/Memory 等 Tab 复用它，不再各自建立
Header 或导航样式。详细状态、拆分和证据要求见 implementation plan 第 12 节。

## P8.1d Model Assignment Contract

`TEAMMATE-MODEL-001` 只负责把队友绑定到一个已经存在的 Provider Preset。它不是第二个模型工作台，
不得复制 API Key、Base URL、协议、高级能力或 provider 检查表单。

默认结构固定为：

```text
Model assignment
  one primary status
  assigned model Select or protected managed state
```

## P8.1f MCP Authorization Contract

`TEAMMATE-MCP-001` manages which existing MCP tools can be used by the current teammate. MCP Server creation,
transport, secrets and tool synchronization remain owned by Settings > MCP Tool Servers. The teammate surface may

The following recommended A-path assumptions define the draft contract, but are **not user-approved yet**. P8.1f
implementation must not start until the user confirms each item:

1. Recommended A: client catalog loading exposes the existing Server/tool query options and loads the complete bounded catalog rather
   than silently accepting the current 100-Server / 200-tool defaults.
2. Recommended A: Core binding replacement validates first and commits atomically; a stale Server cannot delete or partially replace
   the teammate's authoritative bindings.
3. Recommended A: existing `all_current_tools` bindings remain visible and can be converted to explicit selection or cleared, but the
   UI does not create a new automatic-future-tool binding.

The default surface is fixed as:

```text

  Search | All / Authorized / Read / Write-External | Refresh
  optional scoped load/stale/save feedback
  bounded Server DataRow list

    Collapsible tool rows
```

Hard rules:

- Settings Header is the only Reset/Save owner. The MCP content does not render a second title, save status line or

- Server health priority is `disabled > credential migration > auth blocked > checking > failed > expired/needs check
  > ready`. Assignment state is separate neutral text: `paused > automatic > selected > none`; it cannot add a second
  colored primary status.
- Runtime eligibility uses the same current rules as execution: the Server and binding must be enabled; the tool must be
  enabled and allowed by `enabledTools` / `disabledTools`. Only eligible assigned tools count as effective authorization.
- Disabled, Server-excluded and stale selected tools remain visible with a repair reason but cannot be claimed as
  runnable. Unknown selected names appear in a folded unavailable-selection section and can be removed.
- `Authorize all current tools` snapshots currently eligible tools into `mode=selected`; later synchronized tools remain
  unassigned. An existing `all_current_tools` binding explicitly says that future eligible tools are automatic. Its
  Clear action is always enabled, including when zero tools are currently discovered.
- Existing disabled bindings show `Authorization paused`. They remain intact until the user explicitly re-enables or
  clears them; an unrelated Save cannot silently delete them.
- Check uses the existing MCP check endpoint and only the initiating Server is busy. Tool synchronization and Server
  repair use `Manage MCP services`; no Sync, secret or transport editor is copied into this Tab.
- Initial load uses stable Skeleton rows. Background refresh retains the last authoritative snapshot. Failure is local
  persistent `InlineFeedback`; successful Save uses one deduplicated 3000ms global Toast.

- Use shared `Checkbox`, `Input`, `SegmentedControl`, `Button/IconButton`, `DataRow`, `StatusIndicator`, `Badge`,

## P8.1l Danger Zone Contract

`TEAMMATE-DANGER-001` 只升级现有停用与永久删除的展示、确认和反馈边界。`disableAiTeammate`、
`hardDeleteAiTeammate`、事务清理、retention tombstone、频道/运行历史引用和 protected policy 继续由现有
API/Core 负责；本切片不扩大删除对象、清理范围或审计承诺。

默认结构固定为：

```text
Danger zone | one lifecycle status
  Disable teammate
    consequence | scoped failure | Disable
  Hard delete private data
    consequence | scoped failure | Hard delete
  optional shared confirmation Dialog
    truthful cleanup copy | irreversible warning | Reason Field | local failure | Cancel / Hard delete
```

硬规则：

- 普通队友显示 `Disable` 和 `Hard delete`。两种 mutation 使用独立 busy/error，不锁住另一个行动、Settings
  navigation 或无关 Tab；不显示虚构步骤或清理进度。
- 永久删除必须使用 shared `Dialog`，禁止 `window.confirm` / browser alert。Cancel 是初始焦点；一次 Esc、
  外部点击或关闭按钮只关闭一次并恢复触发点。busy 时 Esc、外部点击、关闭和 Cancel 均不可 dismiss。
- Reason 位于 Dialog 内的 shared `Field/Input`，是可选审计原因；失败后保留原值并可原地重试。Input 的
  focus owner 是外层 `focus-within` shell，native input 不得新增 border、shadow 或高度。
- 删除 copy 必须明确：私聊、私有附件、头像、队友记忆和私有绑定被删除；频道和运行历史只保留已删除队友
  引用。UI 不声称删除频道、运行、数据库外对象或扩展 retention。
- protected profile、system teammate 和 Ling Agent 均有可达的只读 Danger Tab，只显示 managed status 和
  explanation；不渲染 disabled fake actions、Reason 或隐藏 mutation trigger，且不得产生 mutation 请求。
- 现有 shell lifecycle callback 是唯一成功 owner。成功后由 callback 关闭/移除当前队友；Dialog 不提前关闭，
  也不本地伪造删除。焦点回到 Settings > Teammate Management 的 Search，找不到时才退到安全主行动。
- 当前 domain 在 mutation 失败时记录错误但不重新抛出。focused controller 以“callback 后目标管理面出现或
  当前 workspace 被移除”为成功信号；有界结算后仍在原身份则显示 local `Unknown error`。这避免假成功，
  但不伪造无法取得的 server detail。
- 旧请求在队友切换后不得把 busy、reason 或 error 带到新身份。Dialog 和 Tab 使用现有 zh/en 文案、主题
  token、shared motion/reduced-motion，并在 1440x960 与 1280x800 保持唯一滚动边界和零横向溢出。
