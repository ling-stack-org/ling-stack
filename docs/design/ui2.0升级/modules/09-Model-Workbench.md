# 模型工作台

## Product Boundary

模型工作台是聊天、媒体和高级模型能力的唯一配置入口。它管理 provider、模型、检查结果、默认聊天模型
和真实 generation capability，不改变聊天、频道、队友或媒体领域的运行状态机。

## Provider And Model Lifecycle

- 用户添加 provider/model 后必须检查通过，才可作为可运行模型使用。
- 第一个检查通过的聊天模型自动成为工作区默认；后续新增模型不自动改变默认，用户可主动切换。
- 新建频道和队友预选当前默认模型，但创建后保存为对象显式选择。更换默认不覆盖显式选择。
- 删除、停用或失效模型前检查频道、队友、普通对话、媒体场景和默认映射引用；存在引用时阻止删除并给出
  可理解修复路径。
- provider、model 和默认映射的服务端响应是权威；前端不从名称或 JSON 猜测能力。

## List

默认列为模型、提供方、能力、状态和操作。名称获得弹性宽度；操作列固定 `184px`、表头与按钮组右对齐。

- 操作顺序为设为默认、检查、编辑、更多，均保持 `32px` 命中区域。设为默认使用星形图标，当前默认使用实心星并不可重复触发；清除默认、停用和删除进入更多菜单。
- 操作列不按百分比扩张，不使用过重竖分隔线。
- 正常模型不显示多枚健康标签；只展示一个主状态。raw endpoint、model ID、checksum 和 provider response
  进入技术详情。
- “全部预设”等状态筛选旁使用独立能力分类：`全部模型 | 视频 | 图片 | 聊天`。视频匹配
  `video_generate`，图片匹配 `image_generate / image_edit`，聊天匹配非 `media-job` 的 `chat`；多能力模型可进入多个分类。
- 搜索匹配用户可见名称、提供方和能力；搜索、状态和能力分类取交集，清除筛选同时恢复三者。长列表内部滚动，刷新保留已有数据。

## Editor And Checks

- 编辑器只展示该 provider/model 真正支持的字段；密钥使用安全输入，不回显完整值。
- 保存与检查分离：保存配置不伪装为可运行，检查成功也不改变用户未确认的默认选择。
- 比例、时长、图片参考等 generation metadata 只来自 resolver 和专用 adapter。未知模型不能通过手填 JSON
  开启未验证能力。
- 检查失败保留输入和上一次权威模型，默认显示产品化原因与下一步，raw health 折叠。
- 聊天模型检查必须从成功响应中解析到可显示文本；HTTP 2xx 但只有 reasoning 或空内容时返回 `empty_response`，并提示检查协议与响应格式。
- scoped busy 只影响发起行或 Dialog；迟到检查响应不能覆盖较新的编辑结果。
- 添加/编辑模型 Dialog 使用明确的 header、可滚动 body、footer 三段式纵向布局；模型发现列表再长、选择项再多，
  header 和 footer 都不得进入滚动区或在 footer 下方留下空白轨道。

## Batch Import Checks

- 批量导入只在请求内完成配置校验、密钥安全存储和模型预设持久化，不等待真实模型推理结束。
- 导入成功后立即关闭 Dialog；需要真实预检的聊天模型持久化为“检查中”，模型列表在刷新或重新打开后仍能恢复该状态。
- daemon 使用全局有界后台队列执行导入预检，最多同时检查 3 个模型；单个上游超时不阻塞其他已导入模型的保存。
- 每个检查结束后写回权威结果并发布 `provider.preflight_checked`；Web 通过既有 control-plane 事件刷新对应行。
- 后台迟到结果不得覆盖用户在导入后又做的编辑、手动检查、停用或删除；daemon 关闭时取消正在进行的网络请求。

## Default Model Semantics

- 默认模型是新对象的预选和未显式绑定对象的回退，不是全局强制覆盖。
- 内置队友可以使用工作区默认；用户给队友显式选过模型后，该选择持续有效。
- 频道的字段名称为“Ling Agent 模型”，只控制频道内置协调/叙述 Agent；频道成员继续使用各自模型。

## Acceptance

覆盖首个模型自动默认、后续模型不抢默认、显式绑定不被默认切换覆盖、引用中删除阻断、检查失败、密钥
脱敏、generation capability、长名称、Light/Dark、`1440x960`、`1280x800` 和 packaged Desktop。
