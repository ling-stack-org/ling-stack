# AI 生成主题产品流程

## Goal

允许用户通过上传图片或描述生成可安装的 `.ling-theme`，同时保持 Theme Pack 是经过
验证的数据包，不让模型生成的 CSS、JavaScript、HTML、selector 或业务状态进入产品。

本设计支持三种明确模式：快速模式、生成模式和高级模式。三种模式共享 Theme Compiler、
安全验证、预览和安装流程，只在 AI 调用与用户控制粒度上不同。

## Function IDs

```text
UI-THEME-GENERATE-QUICK-001     Quick local image-to-theme flow
UI-THEME-GENERATE-STANDARD-001  Image model generation flow
UI-THEME-GENERATE-ADVANCED-001  Planner plus image model flow
UI-THEME-GENERATE-RIGHTS-001    Asset and likeness rights confirmation
UI-THEME-GENERATE-RECOVERY-001  Step-level retry, cancel and draft recovery
```

## Capability Model

产品依赖的是能力角色，不强制要求两个不同模型：

```ts
export interface ThemePlannerCapability {
  readonly acceptsImages: true;
  readonly structuredOutput: true;
  readonly produceThemePlan: (input: ThemePlannerInput) => Promise<ThemePlanCandidate>;
}

export interface ThemeArtworkCapability {
  readonly generateImage: true;
  readonly acceptsReferenceImages: boolean;
  readonly editImage?: boolean;
  readonly supportedAspectRatios: readonly string[];
}
```

- 一个多模态模型如果同时满足规划和生图能力，可以承担两个角色。
- 普通文本模型不能分析上传图片，除非另有本地图像分析结果作为结构化输入。
- 图像模型只负责生成/编辑 artwork，不负责输出最终 manifest。
- 快速模式不要求任何模型。
- 模型选择来自 Model Workbench 已配置且能力匹配的模型，不按模型名称猜测能力。

## Shared Product Flow

```text
Select mode and source
  -> validate source and rights
  -> local image analysis
  -> optional AI plan
  -> optional artwork generation
  -> deterministic Theme Compiler
  -> contrast and security verification
  -> multi-surface preview
  -> user confirms
  -> publish .ling-theme atomically
  -> optionally apply
```

每一步有独立状态和错误所有者。失败后从当前步骤重试，不重新执行已经成功且输入未变化的
昂贵步骤。

## Mode 1: 快速模式

### User Intent

用户已有一张干净背景，希望快速得到协调的主题，不调用外部模型。

### Required Inputs

- 一张 PNG、JPEG 或 WebP。
- 主题名称。
- `colorScheme`，默认由本地分析建议，用户必须能改为 light 或 dark。
- Presentation Profile，默认根据图片与对比度建议。

### Pipeline

1. 读取文件头、MIME、尺寸、像素量和 metadata。
2. 在本地缩略 Canvas 中分析 luminance、dominant/accent palette、saliency、左右信息量。
3. 派生 `focusX/focusY`、safe area、scrim 建议和 route artwork intensity。
4. Theme Compiler 生成完整 semantic tokens。
5. 对正文、muted、focus、status、disabled 和 overlay 做对比度检查。
6. 在 Home、Conversation、Settings、Dialog fixture 中预览。
7. 用户调整焦点、safe area、Profile 和强度后安装。

### No-AI Guarantee

- 图片像素不离开本机。
- 不发送 prompt、palette 或 metadata 到模型服务。
- UI 明确显示“本地生成，不调用模型”。
- 本地分析失败时使用安全 token 候选并要求用户确认，不悄悄切换为云端模式。

### Output

快速模式保留用户原始图片的经清理/重编码副本，并生成 `preview.webp`、manifest 和
generation metadata。不得声称图片由 Ling AI 创作。

## Mode 2: 生成模式

### User Intent

用户上传参考图或输入视觉描述，希望生图模型生成一张没有 UI 的主题背景。

### Required Inputs

- 视觉描述，或一张/多张参考图。
- 已配置且具备 image generation 的模型。
- 主题名称和 `colorScheme`。
- 视觉方向：自然、插画、抽象、科技、节日或自定义描述。
- 素材/肖像权利确认。

### Model Use

- 不调用独立 Planner。
- Ling 使用经过版本化的 Prompt Template，把用户输入、本地图片分析和 Ling safe zone
  规则组合为生图请求。
- 模型返回纯 artwork；tokens、Profile 和 manifest 仍由 Theme Compiler 生成。

### Pipeline

1. 本地分析参考图，仅提取构图、色板、亮度和焦点建议。
2. 生成模式模板构造 prompt 与 negative prompt。
3. 显示模型、目标尺寸和预计调用次数，用户确认后生成。
4. 对生成图执行 UI/text/logo/watermark 风险检查和图片安全验证。
5. Theme Compiler 生成 token 与 Presentation Profile 建议。
6. 用户预览，可重新生成图片或仅重新编译配色。

### Prompt Contract

Prompt 必须包含：

- 输出是独立、连续、边到边的桌面背景，不是应用截图或 UI mockup。
- 参考效果图只用于色板、光线、氛围、主体位置和宽泛构图，不是编辑底稿。
- 不保留窗口、Sidebar、卡片、按钮、输入框、文字、Logo、签名或水印。
- 左右 safe zone 使用 Ling 当前 Home/Sidebar 构图，不硬编码第三方应用坐标。
- 关键主体远离 Sidebar、标题、主行动、Composer 和窗口边缘。
- 保留中间调，能够承受 light/dark scrim，但当前输出只属于一个独立 Theme Pack。
- 人物必须明确成年；没有授权身份图时只能生成原创虚构人物。

### Failure Rules

- 无可用生图模型时模式 disabled，并提供“前往模型工作台”修复动作。
- 模型不支持参考图时，允许纯文本生成，不假装使用了上传图片。
- 输出包含明显 UI/文字时标记为 verification failed，不自动安装。
- 生成失败保留 prompt、参考图和已选模型，可从 Generate 步骤重试。

## Mode 3: 高级模式

### User Intent

用户希望 AI 理解参考图、规划主题结构、生成背景并给出可编辑的主题方案。

### Required Capabilities

- Theme Planner：支持图片输入和严格结构化输出。
- Theme Artwork：支持生图；需要身份保持、扩图或局部修复时还需 image edit。
- 两个角色可选择同一个模型，也可分别选择。

### Additional Controls

- Planner 模型与生图模型。
- Presentation Profile。
- artwork slot：shell background、home hero、可选 corner decoration。
- 风格、情绪、材质、光线、色板和主视觉位置。
- safe area、focus point、Home/Conversation artwork intensity。
- 允许生成的变体数量，第一阶段为 `1..4`。
- 原始计划 JSON、prompt 和 negative prompt 放在 Advanced Details，默认折叠。

### Planner Output

Planner 只能返回严格结构化候选：

```ts
export interface ThemePlanCandidate {
  readonly title: string;
  readonly summary: string;
  readonly colorScheme: "light" | "dark";
  readonly recommendedProfileId: LingPresentationProfileId;
  readonly palette: readonly ThemePaletteCandidate[];
  readonly artwork: {
    readonly prompt: string;
    readonly negativePrompt: string;
    readonly focusX: number;
    readonly focusY: number;
    readonly safeArea: "left" | "right" | "center" | "none";
    readonly preferredAspectRatio: "16:9" | "16:10" | "21:9";
  };
  readonly rightsFlags: readonly ThemeRightsFlag[];
  readonly warnings: readonly ThemePlanWarning[];
}
```

禁止字段：CSS、selector、HTML、JS、font URL、DOM path、component name、ViewId、Logo
replacement 和业务文案 replacement。未知字段由 parser 丢弃并记录 diagnostics。

### Pipeline

1. Planner 分析用户输入和参考图片，返回 plan candidate。
2. Ling 校验 JSON、范围、rights flags 和 Profile allowlist。
3. 用户在生成前查看产品化摘要，可展开 prompt details。
4. Artwork model 生成一个或多个纯背景候选。
5. 用户选择候选，必要时执行一次扩图/修复。
6. Theme Compiler 根据最终图片重新分析并生成 manifest，不盲信 Planner palette。
7. 全部 fixtures 通过后才能安装。

### Advanced Fallback

- Planner 不可用时可降级到生成模式，但必须提示用户并要求确认。
- Artwork model 不可用时保留计划草稿，不生成“空主题”。
- Planner JSON 不合法时最多自动重试一次结构化输出，之后显示可修复错误。
- 不能用普通文本输出正则拼接 Theme Pack manifest。

## Source Image Classes

上传时必须让用户选择或由系统建议来源类型：

| Source | Allowed use | Required warning |
|---|---|---|
| clean wallpaper | 可直接快速模式或作为生成参考 | 检查 Logo、水印和授权 |
| UI screenshot/effect mockup | 只能作为生成参考 | 不可直接导入，必须生成全新纯背景 |
| personal photo | 可用于本地提色；人物生成需权利确认 | 不默认上传到模型 |
| identity reference | 仅高级授权流程 | 明确成年、肖像和再分发权利 |
| third-party artwork | 仅用户有权使用时 | 导入成功不代表可商用/分发 |

## Image Output Rules

- 推荐母版 `2560x1440`，宽度至少 `2000px`，16:9。
- 支持生成器时优先请求最高质量 16:9，不把非 16:9 强行拉伸。
- Compiler 可以生成预览和受控裁切，不凭空补充图像细节。
- 可选变体：`16:10` 和 `21:9`；没有变体时使用 focus/safe area cover。
- 输出不得包含 UI、Logo、品牌、签名、水印、可读文字和伪控件。
- 图片重编码清除非必要 metadata，保留必要版权/归属文件而不是隐写 metadata。

## Progress And Recovery

统一步骤：

```text
Validate -> Analyze -> Plan? -> Generate? -> Compile -> Verify -> Ready
```

- 当前步骤显示 running；已经完成步骤显示结果摘要。
- 取消只停止未完成模型请求，不删除源图和草稿。
- 用户修改影响上游的字段时，只失效相关下游结果。
- 页面关闭后草稿可以本地恢复，但不自动恢复未确认的模型调用。
- 成功安装后清理临时生成文件；用户选择保存草稿时保留受管副本。
- 每个失败显示步骤名、产品化原因、重试和修复路径；原始 provider 响应进 Details。

## Cost And Privacy

- 任何模型调用前显示将使用的模型、图片数量和预计调用次数。
- 快速模式明确标记零模型调用。
- 生成/高级模式不在用户未确认时上传本地图片。
- API Key 由既有 Model Workbench/provider 层管理，Theme Studio 不读取或展示 secret。
- 生成日志不记录图片字节、完整 prompt 中的私人路径或 provider secret。

## Install Result

生成主题的 registry source 为 `local-generated`。manifest 包含非执行的生成元数据：

```ts
export interface LingThemeGenerationMetadata {
  readonly mode: "quick" | "generate" | "advanced";
  readonly createdAt: string;
  readonly plannerModelRef?: string;
  readonly artworkModelRef?: string;
  readonly promptTemplateVersion?: string;
  readonly sourceAssetCount: number;
}
```

模型引用只保存非秘密的 provider/route display reference。用户导出主题时可以选择移除
生成元数据，但不能移除 license/attribution warning。

## Codex Dream Skin Reference Adaptation

参考资料：

- [macOS workflow](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/macos/README.md)
- [Windows workflow](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/windows/SKILL.md)
- [platform comparison](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/docs/platforms.md)
- [reference background prompt guide](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/docs/reference-background-prompt-guide.md)
- [background generation directions](https://github.com/Fei-Away/Codex-Dream-Skin/blob/main/docs/background-generation-prompts.md)

Ling 采用并重写为本产品合同的部分：

- 纯背景原则：不把 UI、文字、按钮、Logo 和窗口 chrome 烘焙进图片。
- `focusX/focusY`、safe area、task/route artwork mode。
- 本地亮度、色板、显著区域和左右信息量分析。
- Home 表现丰富、Conversation/Settings/diagnostics 自动降噪。
- 图片尺寸/MIME/path 检查、staging、atomic publish、restore 和跨平台验证。
- 参考图职责、负面提示词、裁切安全、人物成年和素材权利确认。

Ling 不直接采用：

- CDP 注入、MutationObserver、DOM class coupling、大量 selector 或 `!important`。
- Codex 固定的 `x=0%-52%`、`x=62%-88%` 构图坐标；Ling 根据自己的 Sidebar、Home、
  Composer 和窗口尺寸建立 fixture 后确定 safe zone。
- `appearance:auto` 让一个主题内部自动切 Light/Dark；Ling 的 Light/Dark 是独立 Theme Pack。
- Codex 品牌文案、项目标签、状态文字、人物预设和第三方素材。
- 带 UI 的概念效果图直接作为 wallpaper 或 preview truth。

Dream Skin 的软件方法可作为 MIT 参考，但人物、肖像、第三方图像和效果截图需要单独权利
审查。Ling 的 Prompt Template 应重新编写并版本化；如果直接复制软件代码或较长文档片段，
必须保留对应版权与许可声明。

## Acceptance

- 快速模式断网可用，图片不离开本机。
- 生成模式只有一个生图能力也能完成，不强制配置文本模型。
- 高级模式支持同一模型或两个模型承担 Planner/Artwork 角色。
- 三种模式最终都经过同一个 deterministic Theme Compiler。
- 模型输出无法写入 CSS、JS、HTML、selector、Logo 或业务文案。
- 每个步骤可取消、重试和恢复，失败不会安装半完成主题。
- UI screenshot 不可直接作为背景安装，必须生成新的纯 artwork。
- `1280x800`、`1440x960`、大屏和 macOS/Windows 预览均通过后才能标记 Ready。
