# 独立主题包产品模型

## Goal

建立一个可以一键切换、可扩展到 Electron Desktop、不需要重写 Feature CSS 的
外观模型。主题只改变产品的视觉表面，不改变产品语义。

## Implementation Status

The P2A product model is `implemented` as of 2026-07-18:

- `ThemeSelection` supports fixed and System mappings;
- `ling-light` and `ling-dark` are independent complete built-in manifests;
- explicit new Theme Pack selection has priority over daemon legacy input;
- missing or invalid selections fall back by expected color scheme without rewriting the selection;
- Web、Desktop main and Computer Use PiP share validated semantic variables.

ThemePicker/import archive UI、Presentation Profile rendering and generated themes remain later work.
See [Ling UI 2.0 验收总规范](../03-UI2.0验收总规范.md).

## Theme Pack Is The Unit

所有主题包平级存在：

```text
ling-light
ling-dark
graphite
forest-mist
midnight-aurora
user-custom-<id>
```

`ling-light` 和 `ling-dark` 是两个独立内置主题，不是同一主题下的两个颜色分支。

主题可以通过 `familyId` 在选择界面中归组，例如 `ling-light` 和 `ling-dark`
都属于 `ling` family。Family 只是展示元数据，不产生 CSS 继承、token 合并或自动配对。

## Selection Model

```ts
export type ThemeSelection =
  | {
      readonly mode: "fixed";
      readonly themeId: string;
    }
  | {
      readonly mode: "system";
      readonly lightThemeId: string;
      readonly darkThemeId: string;
    };
```

Default selection:

```ts
{
  mode: "system",
  lightThemeId: "ling-light",
  darkThemeId: "ling-dark",
}
```

### Fixed

- 用户选择一个具体 Theme Pack。
- 操作系统明暗变化不影响当前主题。
- 主题被删除或无法加载时，根据该主题 `colorScheme` 回退到
  `ling-light` 或 `ling-dark`。

### System

- `System` 是解析策略，不是 Theme Pack ID。
- 系统浅色时选择 `lightThemeId`，系统深色时选择 `darkThemeId`。
- 第一阶段设置界面只提供“跟随系统”开关，映射固定为
  `ling-light` / `ling-dark`。
- 未来可以增加高级映射，例如系统浅色使用 `sakura`，深色使用 `midnight`；
  这不属于第一阶段界面范围。

## Resolved State

```ts
export interface ResolvedThemeState {
  readonly selection: ThemeSelection;
  readonly themeId: string;
  readonly colorScheme: "light" | "dark";
  readonly source: "built-in" | "local-import" | "local-generated" | "fallback";
}
```

Theme resolution 不依赖当前 ViewId、Settings section、workspace、channel 或业务状态。

## Display Rules

- 设置页分开展示“跟随系统”和“主题”。
- 关闭跟随系统时，主题列表的选中项是唯一实际主题。
- 开启跟随系统时，主题列表显示当前解析结果，但不把 `System` 渲染成主题卡。
- 内置主题和导入主题使用同一 ThemePicker 语法，仅来源和可删除性不同。
- 主题名称、作者、来源和许可证是元数据，不能覆盖产品文案。

## Allowed Visual Changes

- App、panel、elevated、subtle、pressed 等 surface。
- 文字、边框、focus、selection、scrollbar 和 accent。
- success、warning、danger、info 的语义色组。
- 阴影强度、Desktop 材质和经过限制的背景资源。
- 原生 `color-scheme`、code surface 和图表语义色。
- 选择 Ling 内置、版本化且通过验收的 Presentation Profile。
- 调整 Profile 允许的 surface/artwork intensity、焦点、安全区和固定装饰资源。

## Forbidden Visual Changes

- 控件高度、字号、行高、间距、栅格、页面宽度和响应式断点。
- Button、Dialog、Drawer、Menu、Toast 和 Composer 的结构。
- Lucide 图标映射、Logo、favicon、队友头像和内容资产。
- z-index、focus order、键盘行为、loading 范围和业务状态。
- 通过主题隐藏错误、诊断、审批、危险操作或 disabled reason。
- 上传 Profile CSS、DOM、selector、页面 JSX、任意坐标或未登记装饰槽位。

## Presentation Profile Boundary

Presentation Profile 是 Ling 应用代码拥有的表现配方，用于把同一 Theme Pack 的 token 和
artwork 安全地呈现在 Home、Sidebar、Conversation、Settings 和 Overlay。Theme Pack 只保存
Profile ID 和 allowlisted 参数，不包含实现。

第一阶段 Profile：

```text
ling-standard
ling-glass
ling-immersive
ling-illustrated
```

Profile definition 由应用代码注册和版本化，主题包只能选择 ID 与 allowlisted 强度。内置 Profile：

- `ling-standard`：高密度和管理页面的默认清晰表面；
- `ling-glass`：仅在平台支持时使用受控材质，始终提供不透明 fallback；
- `ling-immersive`：Home 和低密度会话可显示 ambient artwork，Settings、表格、审批和诊断保持
  token-only；
- `ling-illustrated`：允许登记的透明角落装饰，不允许伪控件、文字、Logo 或水印。

Profile 决定 slot 坐标、安全区、scrim、断点和 z-index。Theme Pack 不能覆盖 Profile definition，
Feature 也不能根据 Profile ID 编写私有样式分支。artwork 只允许在资源就绪后淡入；forced-colors、
reduced transparency、窄窗口或资源失败时回退到清晰表面。

## Generated Themes

- 快速模式使用本地图像分析，不要求模型或网络。
- 生成模式只要求一个具备 image generation 的模型。
- 高级模式使用结构化多模态 Planner 和 Artwork 能力；两个角色可以由同一模型承担。
- 模型只能生成 plan candidate 和 artwork，最终 manifest/tokens 由 Theme Compiler 生成。
- 生成主题与本地导入主题进入同一 Registry，source 标记为 `local-generated`。

## Persistence Boundary

主题是用户的客户端外观偏好，不是 workspace 业务数据。UI 2.0 第一阶段：

- Web 使用 client-local preference store 和首帧 bootstrap mirror。
- Electron 使用 Desktop settings adapter 和 app data 目录。
- 当前 daemon 中 `system/light/dark` workspace setting 只作为 legacy migration input。
- 不向现有 daemon contract 写入任意 Theme Pack ID。
- 未来跨设备同步需要单独的 user preference API 设计，不由 UI 2.0 本地状态伪造。

## Accessibility

- Theme Pack 必须通过正文、muted text、focus、danger 和 disabled 对比度检查。
- 语义不得只依赖颜色；Icon、文字和 ARIA 保持不变。
- 背景资源必须有可读 scrim 和关闭能力。
- forced-colors、reduced transparency 或资源失败时回到清晰的 token-only surface。

## Non-Goals

- 不做主题商店、远程主题市场或在线执行包。
- 不允许主题修改导航 IA、页面 JSX 或业务能力。
- 不在第一阶段提供高级 System 主题映射编辑器。
- 不把 Codex Dream Skin 的 CDP 注入和 DOM selector 覆盖引入 Ling。
- 不允许模型输出直接成为 runtime CSS、Theme Pack manifest 或业务文案。
