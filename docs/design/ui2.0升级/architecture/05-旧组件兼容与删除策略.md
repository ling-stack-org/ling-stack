# 旧组件兼容与删除策略

## Existing Facade

`apps/web/src/shared/components` 在迁移期间保留，但组件分为：

- **wrap**：API 保留，内部改用 UI 2.0；当前仍适用的例子是 `StatusBadge`。
- **move**：无业务依赖但仍有通用价值的组件迁入 package；当前没有为 OperationEmptyState 保留第二套 API。
- **domain**：保留 Web/feature，如 ArtifactRow、UsedMemorySummary。
- **delete**：被新 primitive 完全替代且无引用的实现。

T13-H 已验证 `ActionMenuItem` 属于 **delete**：所有调用迁入 shared Radix Menu 后，component、export 和
87 行 compatibility CSS 一并删除，没有在 package 建立第二个 Menu API。
`SelectControl` 与 `CreateDialogShell` 的历史决策都是 **wrap then delete**；`OperationEmptyState` 直接属于
**delete**。T13-P.3-R 已确认三者完成删除，不得把它们重新登记为现役 facade。

## Migration Contract

- 先增加新实现和 wrapper，再迁移调用点，最后删旧 CSS。
- 不在同一 PR 大规模重命名测试 selector 和改变业务行为。
- compatibility export 必须标记 deprecated，并在状态看板登记删除切片。
- 新代码不得继续使用 deprecated export。

## P3 Compatibility Budget

P3 foundation 使用 lint budget 防止旧 facade 在页面迁移前继续扩张。2026-07-18 基线为：

| Facade | Caller files | Next owner |
|---|---:|---|
| `SelectControl` | 43 | U3 controls/forms，逐模块迁到 `Select` |
| `CreateDialogShell` | 7 | 对应业务 Dialog/Drawer 切片 |
| `OperationEmptyState` | 6 | U1/U2 data display，逐模块迁到 `EmptyState` |
| `StatusBadge` | 26 | 各模块状态 view-model + `Badge/StatusIndicator` |

上表是 P3 foundation 的历史预算 `43 / 7 / 6 / 26`，不得用当前数字覆盖。预算是上限，不是目标值；
任何新增调用都会让 Web lint 失败，调用数只能保持或下降。

### T13-P.3-R Current Closeout

| Facade | Final guard | Canonical current status |
|---|---:|---|
| `SelectControl` | `0/0` | component、export、生产引用与 `select-controls.css` 已删除；调用方直接使用 shared `Select` |
| `CreateDialogShell` | `0/0` | component、export 与生产引用已删除；Channel Create 直接使用 shared `Dialog` / `Select` |
| `OperationEmptyState` | `0/0` | T13-P.2-D 删除；Council 直接使用 shared `EmptyState` |

三项均已满足“调用归零、语义 E2E、旧 owner 删除”的 gate。`StatusBadge`、ActionMenu 之外的遗留视觉
class selector 和其他 compatibility 工作仍按各自切片推进；不得把三项 closeout 解释为全产品 legacy
cleanup 已完成。

## Delete Gate

删除旧组件前必须满足：

1. `rg` 无生产引用。
2. 相关 E2E 已使用新语义 selector。
3. `ling-light` / `ling-dark` 和两种 viewport 通过。
4. 对应 CSS 无引用并删除。
5. 覆盖矩阵状态至少为 `implemented`。

## Large Files

超过 800 行的文件只能接入 wrapper，不追加新的主要 UI 逻辑。超过 1200 行的文件必须先
抽出 focused component/controller，再迁移视觉。
