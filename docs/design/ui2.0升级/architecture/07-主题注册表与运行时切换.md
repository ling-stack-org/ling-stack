# 主题注册表与运行时切换

## Goal

建立一个 Web 与 Electron Desktop 共用的 Theme Pack 注册表和切换管线。
主题切换只改变根节点语义 token，不卸载 React tree、不刷新页面、不修改业务状态。

## Implementation Status

P2A runtime is `implemented`. It includes independent built-ins、manifest and
bootstrap validation、fixed/System resolution、fallback、atomic DOM apply/rollback、Web storage、
first paint and the revisioned Desktop/PiP bridge. P7C.1 extends this boundary with Web-verified
ThemePicker actions、strict bundle import、IndexedDB v2 package/preview storage and lifecycle rollback.
It still does not include runtime imported artwork、Desktop native package persistence or Theme Studio.

Acceptance follows [Ling UI 2.0 验收总规范](../03-UI2.0验收总规范.md).

## Module Boundary

```text
packages/ui-react/src/theme/

apps/desktop/
  main/renderer-theme-store.ts

  renderer/computer-use-preview/preview-theme-controller.ts
```

- `ui-react` 拥有 types、内置主题、验证、解析和 CSS variable 映射。
- Web adapter currently owns selection/bootstrap persistence、IndexedDB manifests、i18n and system
  appearance events. File archive import remains a later adapter.
- Desktop main owns the validated revision store; Desktop renderers only receive the narrow snapshot.
- Feature 页面不导入 registry、manifest 或 storage adapter，只消费语义 token。
- Theme 模块不导入 API Client、Core、路由、workspace domain 或 Settings feature。

## Registry Contract

```ts
export class ThemeRegistry {
  list(): readonly RegisteredTheme[];
  get(themeId: string): RegisteredTheme | undefined;
  resolve(selection: ThemeSelection, systemScheme: LingColorScheme): ResolvedThemeState;
  install(
    manifest: unknown,
    source: "local-import" | "local-generated",
    installedAt?: string,
  ): ThemeInstallResult;
  uninstall(themeId: string): boolean;
}
```

```ts
export interface RegisteredTheme {
  readonly manifest: LingThemePackManifest;
  readonly source: "built-in" | "local-import" | "local-generated";
  readonly state: "ready" | "incompatible" | "missing-asset" | "invalid";
  readonly installedAt?: string;
  readonly validationIssue?: string;
}
```

Built-in registry 在 package 初始化时同步可用。本地主题异步合并，但当前已选主题的
验证 bootstrap snapshot 必须在首帧前可读。

## Root Attributes

```html
<html
  data-ui-theme="ling-dark"
  data-color-scheme="dark"
  data-theme-selection="fixed"
  data-ui-presentation="ling-immersive"
  data-client="desktop"
>
```

| Attribute | Meaning |
|---|---|
| `data-ui-theme` | 当前实际解析后 Theme Pack ID |
| `data-color-scheme` | Theme Pack 声明的 `light` / `dark` |
| `data-theme-selection` | `fixed` / `system` selection strategy |
| `data-ui-presentation` | 当前已验证的 app-owned Presentation Profile ID |
| `data-client` | `web` / `desktop` surface adapter |

`data-theme="light|dark"` 只在 legacy 迁移期保留为 alias，U13 删除。

## Resolution Algorithm

```text
read ThemeSelection
  -> if fixed: resolve themeId
  -> if system: read OS scheme, resolve mapped themeId
  -> validate registered theme state
  -> if invalid/missing: choose ling-light or ling-dark by expected scheme
  -> produce ResolvedThemeState
```

- System event 只在 `selection.mode === "system"` 时触发主题切换。
- Fixed 主题不随 OS 变化，即使它的 `colorScheme` 与 OS 当前外观不同。
- Registry 不为主题生成相反颜色版本。
- System mapping 中任一主题不可用时，只回退当前需要的那一个内置主题。

## First-Paint Bootstrap

首帧不能等待 React effect、daemon 请求或 IndexedDB 异步查询。

### Built-In Theme

- HTML/renderer bootstrap 同步读取小型 ThemeSelection mirror。
- 内置 Theme Pack 的 CSS variables 已编译到 package CSS，设置 `data-ui-theme` 即生效。
- 同一步设置 `data-color-scheme`、`data-theme-selection` 和 native `color-scheme`。

### Imported Theme

- 导入成功时生成一份经验证、按允许变量排序的 bootstrap snapshot。
- snapshot 只包含 Theme Pack ID、`colorScheme`、已验证 Profile ID 和语义 CSS variable map，
  不包含图片字节。
- bootstrap 将 snapshot 写入专用 `<style id="ling-theme-bootstrap">` 或根节点 style map，
  并同步设置 `data-ui-presentation`。
- React/renderer 启动后重新验证 registry，成功后接管；不一致时原子回退。

### Bootstrap Storage

```text
ling-stack.themeSelection
ling-stack.themeBootstrapSelection
ling-stack.themeBootstrapSnapshot
```

- Web 使用 localStorage 作为首帧 mirror，但不存储大图或未验证 manifest。
- Desktop 由 preload 在创建 renderer 前注入已验证 bootstrap state。
- 无法解析、版本不支持或校验失败时使用系统映射的内置主题。

## Runtime Apply Transaction

```text
validate target theme
  -> resolve registered Presentation Profile
  -> prepare variable map, route policy and artwork URLs
  -> preload/decode required artwork
  -> mark root data-theme-transition="preparing"
  -> apply theme id, scheme, Profile and variables in one animation frame
  -> update native color-scheme
  -> confirm computed sentinel tokens
  -> persist selection and bootstrap mirror
  -> remove preparing state
```

- 持久化只在 computed sentinel token 验证成功后发生。
- 任一步失败恢复上一个 ResolvedThemeState，不让页面停在混合 token 状态。
- 切换不使用整页 opacity 动画、不添加白幕/黑幕过渡。
- 颜色可使用 shared `180ms` transition，但 layout、size、transform 和 scroll 不过渡。
- artwork 只允许在资源准备完成后做 `180ms` opacity crossfade，不显示空白/黑色中间帧。
- reduced motion 下直接替换 token。

## CSS Application

内置主题编译为 token-only selector：

```css
@layer ling.tokens.theme {
  :root[data-ui-theme="ling-light"] { /* semantic variables */ }
  :root[data-ui-theme="ling-dark"] { /* semantic variables */ }
}
```

导入主题通过验证后的 variable map 写入单一 runtime style owner。

- Feature CSS 禁止出现 `data-ui-theme="<id>"`。
- Feature CSS 禁止出现 `data-ui-presentation="<id>"`；只有共享 presentation layer 可消费。
- Feature CSS 禁止依赖 `data-color-scheme` 修补具体组件；需求必须提升为 token。
- Desktop 使用 `ling.tokens.client` 层覆盖 surface token，不复制主题 selector。
- Theme Pack 无法修改 cascade order、z-index 或 component state selector。

## Storage Adapters

### Web

- Selection 和 bootstrap snapshot 客户端本地存储。
- 导入 manifest/assets 使用 IndexedDB。
- localStorage 写入失败时回滚到上一个主题，并显示不阻塞 warning Toast；不能只改视觉而丢失持久化。
- daemon 的 legacy `system/light/dark` 只在没有显式 ThemeSelection 时应用，并只更新 legacy
  first-paint mirror；它不能被误存为新的显式 Theme Pack 选择。

### Desktop

- Selection 使用 Desktop settings store。
- Theme bundles 使用 app data 目录和 atomic directory publish。
- Renderer 不获得任意文件系统访问；通过窄 preload API 导入、列出和删除主题。
- macOS/Windows 使用相同 manifest 和 registry，仅存储路径和窗口材质 adapter 不同。

## Theme Compiler And Model Boundary

- Quick 模式只在本地从图片提取配色并生成受限 token；上传图片不发布为运行时背景。
- Generate/Advanced 模式只能输出结构化 plan candidate 和 artwork candidate，不能输出可执行
  CSS、selector、DOM path、HTML、JavaScript 或最终 manifest。
- Theme Compiler 是模型输出进入 Registry 的唯一入口，负责 allowlist、对比度、Profile、资源、
  license 和 schema 验证。模型或 Feature 不得直接调用 `install()` 绕过 Compiler。
- Provider、模型 ID、prompt 和原始响应属于生成过程，不参与运行时解析；密钥不得写入主题包。

## Desktop Renderer Synchronization

- Desktop main 持有带单调 revision 的已验证主题快照；主窗口、PiP 和 utility renderer 只通过
  typed preload/IPC 接收该快照，不读取 Web storage 或任意本地路径。
- Renderer 忽略旧 revision。新窗口必须在首个可见帧前获得 bootstrap snapshot；缺失时按
  color scheme 使用内置安全 token，不等待网络或 daemon。
- 主题、locale 和 current-session capability 是不同快照，不得合并为无类型对象。
- 单个 renderer 加载或资源失败只回退该窗口，不得破坏主窗口已应用主题。
- Desktop 原生主题包发布仍由
  [Desktop Theme Pack Persistence Plan](../modules/settings/10-Desktop-Theme-Pack-Persistence-implementation-plan.md)
  管理。

## Current P2A Context API

```ts
export interface ThemeContextValue {
  readonly selection: ThemeSelection;
  readonly resolved: ResolvedThemeState;
  readonly themes: readonly RegisteredTheme[];
  readonly setFixedTheme: (themeId: string) => Promise<void>;
  readonly setFollowSystem: (enabled: boolean) => Promise<void>;
  readonly installTheme: (manifest: LingThemePackManifest) => Promise<RegisteredTheme>;
  readonly removeTheme: (themeId: string) => Promise<void>;
}
```

`importTheme(file)` and `installGeneratedTheme(candidate)` are later adapter APIs. They may call the
P2A `installTheme` boundary only after archive/Compiler verification; Feature code cannot pass model
output or an unverified file directly to Registry.

Feature 若需要 code editor/canvas 的当前配色，只读 `resolved.colorScheme` 或共享派生 token，
不根据 Theme Pack ID 写分支。

## Failure Model

| Failure | Required behavior |
|---|---|
| Unknown theme ID | fallback by expected colorScheme, preserve invalid selection for diagnostics |
| Imported theme missing | fallback, mark registry entry missing, ThemePicker offers remove/reimport |
| Invalid bootstrap snapshot | ignore and clear snapshot, use built-in system mapping |
| Runtime variable application fails | restore previous resolved state, error Toast + diagnostic details |
| Presentation Profile unknown/unsupported | reject install/apply; do not guess fallback silently |
| Required artwork decode fails | keep tokens, disable artwork through verified fallback, report repair state |
| Generated theme publish succeeds but apply fails | keep installed theme ready, restore previous active theme |
| OS scheme event during fixed mode | no theme change |
| OS scheme event during system mode | resolve mapped theme atomically |
| Theme removed while active | switch to built-in fallback before delete |

## Tests

- Registry duplicate ID、reserved namespace、unknown schema、missing tokens、invalid colors、fallback。
- Fixed/System resolution and OS event behavior。
- First frame dataset and computed token match final state。
- Theme switch while Dialog、Menu、Composer、Terminal 和 Right Dock 处于开启状态。
- Apply failure restores previous theme without unmounting page or losing focus。
- Web local storage failure and Desktop adapter failure produce productized feedback。
- macOS/Windows representative renderer uses the same Theme Pack ID and semantic tokens。
- four built-in Presentation Profiles use the same route policy and fallback contract across clients。
- generated Theme Pack follows the same Registry/apply transaction as imported themes。

Cross-platform signed package、Windows DPI/high contrast and Desktop-native package persistence remain open,
so the runtime is `implemented`, not full-product `release-ready`. Current test counts and screenshots belong to
CI/Release artifacts rather than this contract.
