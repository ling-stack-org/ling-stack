# 官方主题注册表与运行时切换

## Goal

建立 Web 与 Electron Desktop 共用的官方 Theme Pack 注册表和切换管线。主题切换只改变根节点语义 token、scene metadata 和 presentation policy，不卸载 React tree、不刷新页面、不修改业务状态。

## Implementation Status

经典 built-in runtime 已实现。官方场景主题、scene renderer 和“只保留官方主题”的注册表边界按[实施方案](../../full-window-theme-background-implementation-plan.md)进入当前交付。最终状态以当前验证报告为准。

Acceptance follows [Ling UI 2.0 验收总规范](../03-UI2.0验收总规范.md) and [官方场景主题与背景验收矩阵](../../full-window-theme-background-acceptance-matrix.md).

## Module Boundary

```text
packages/ui-react/src/theme/
  types.ts
  token-map.ts
  validate-theme.ts
  theme-registry.ts
  apply-theme.ts
  built-ins/
    ling-light.ts
    ling-dark.ts
    ling-breeze.ts
    ling-ocean.ts
    ling-night.ts

packages/ui-react/src/theme-scene/
  SceneArtwork.tsx
  scene definitions

apps/web/src/
  theme.tsx
  index.html
  app/DesktopThemeBridge.tsx
  shared/ui/background/

apps/desktop/
  main/renderer-theme-store.ts
  main/backgrounds/
  shared/renderer-theme.ts
  renderer/computer-use-preview/preview-theme-controller.ts
```

- `ui-react` 拥有 types、内置主题、scene renderer、验证、解析和 CSS variable 映射。
- Web adapter owns selection/bootstrap persistence、i18n、system appearance events and user background storage.
- Desktop main owns validated revision stores; renderers receive narrow typed snapshots.
- Feature 页面不导入 registry、manifest 或 storage adapter，只消费语义 token。
- Theme 模块不导入 API Client、Core、路由、workspace domain 或 Settings feature。

## Registry Contract

```ts
export class ThemeRegistry {
  list(): readonly RegisteredTheme[];
  get(themeId: string): RegisteredTheme | undefined;
  resolve(selection: ThemeSelection, systemScheme: LingColorScheme): ResolvedThemeState;
}
```

```ts
export interface RegisteredTheme {
  readonly manifest: LingThemePackManifest;
  readonly source: "built-in";
  readonly state: "ready" | "incompatible" | "invalid";
  readonly validationIssue?: string;
}
```

Built-in registry 在 package 初始化时同步可用。产品运行时不安装 local-import/local-generated manifests；历史 fixed selection 在 registry resolve 时按颜色模式回退到官方浅色或深色主题。

底层 storage 中仍可能存在历史主题数据，但它不进入可用 registry。清理历史数据是单独迁移任务，不在主题切换路径中执行。

## Root Attributes

```html
<html
  data-ui-theme="ling-breeze"
  data-color-scheme="light"
  data-theme-selection="fixed"
  data-ui-presentation="ling-illustrated"
  data-client="desktop"
  data-background-source="theme-scene"
>
```

| Attribute | Meaning |
|---|---|
| `data-ui-theme` | 当前实际解析后官方 Theme Pack ID |
| `data-color-scheme` | Theme Pack 声明的 `light` / `dark` |
| `data-theme-selection` | `fixed` / `system` selection strategy |
| `data-ui-presentation` | 当前已验证的 app-owned Presentation Profile ID |
| `data-client` | `web` / `desktop` surface adapter |
| `data-background-source` | `theme-solid` / `theme-scene` / `local-image` / `local-video` |

`data-theme="light|dark"` 只在 legacy 迁移期保留为 alias，后续删除。

## Resolution Algorithm

```text
read ThemeSelection
  -> if fixed: resolve themeId
  -> if system: read OS scheme, resolve mapped themeId
  -> validate registered built-in theme state
  -> if invalid/missing/non-built-in: choose ling-light or ling-dark by expected scheme
  -> produce ResolvedThemeState
```

- System event 只在 `selection.mode === "system"` 时触发主题切换。
- Fixed 主题不随 OS 变化，即使它的 `colorScheme` 与 OS 当前外观不同。
- Registry 不为主题生成相反颜色版本。
- System mapping 中任一主题不可用时，只回退当前需要的那一个官方主题。

## First-Paint Bootstrap

首帧不能等待 React effect、daemon 请求或 IndexedDB 异步查询。

- HTML/renderer bootstrap 同步读取小型 ThemeSelection mirror。
- 内置 Theme Pack 的 CSS variables 已编译到 package CSS，设置 `data-ui-theme` 即生效。
- 同一步设置 `data-color-scheme`、`data-theme-selection` 和 native `color-scheme`。
- 非 built-in 历史 bootstrap snapshot 不再授权给首帧，避免旧导入主题闪回。
- 无法解析、版本不支持或校验失败时使用系统映射的官方主题。

## Runtime Apply Transaction

```text
validate target theme
  -> resolve registered Presentation Profile
  -> prepare variable map, route policy and scene metadata
  -> mark root data-theme-transition="preparing"
  -> apply theme id, scheme, Profile and variables in one animation frame
  -> update native color-scheme
  -> confirm computed sentinel tokens
  -> persist selection and bootstrap mirror
  -> remove preparing state
```

- 持久化只在 computed sentinel token 验证成功后发生。
- 任一步失败恢复上一个 ResolvedThemeState，不让页面停在混合 token 状态。
- 切换不使用整页 opacity 动画、不添加白幕/黑幕过渡。
- 颜色可使用 shared `180ms` transition，但 layout、size、transform 和 scroll 不过渡。
- scene 直接随主题切换；reduced motion 下不使用过渡。

## Scene Rendering

Scene renderer 是共享应用组件，不是 Theme Pack 输入：

- `WorkspaceBackgroundLayer` 在无自定义媒体时读取 `resolved.manifest.scene` 并渲染对应 `SceneArtwork`。
- 主题列表使用同一个 scene renderer 生成缩略图。
- scene 资源不经过 IndexedDB、用户路径、网络或压缩包。
- 保护路由由 presentation policy 回退实底，不显示 scene。

## CSS Application

内置主题编译为 token-only selector：

```css
@layer ling.tokens.theme {
  :root[data-ui-theme="ling-light"] { /* semantic variables */ }
  :root[data-ui-theme="ling-dark"] { /* semantic variables */ }
  :root[data-ui-theme="ling-breeze"] { /* semantic variables */ }
}
```

- Feature CSS 禁止出现 `data-ui-theme="<id>"`。
- Feature CSS 禁止出现 `data-ui-presentation="<id>"`；只有共享 presentation layer 可消费。
- Feature CSS 禁止依赖 `data-color-scheme` 修补具体组件；需求必须提升为 token。
- Desktop 使用 `ling.tokens.client` 层覆盖 surface token，不复制主题 selector。
- Theme Pack 无法修改 cascade order、z-index 或 component state selector。

## Storage Adapters

### Web

- Selection 使用客户端本地存储。
- 用户背景媒体使用独立 IndexedDB stores，与主题 registry 分离。
- localStorage 写入失败时回滚到上一个主题，并显示不阻塞 warning；不能只改视觉而丢失持久化。
- daemon 的 legacy `system/light/dark` 只在没有显式 ThemeSelection 时应用，并只更新 legacy first-paint mirror。

### Desktop

- Selection 使用 Desktop settings store。
- 用户背景媒体使用 app data 下受管 `backgrounds/` 目录和 atomic publish。
- Renderer 不获得任意文件系统访问；通过窄 preload API 读取、准备、提交和释放背景。
- macOS/Windows 使用相同 manifest 和 registry，仅存储路径和窗口材质 adapter 不同。

## Current Context API

```ts
export interface ThemeContextValue {
  readonly selection: ThemeSelection;
  readonly resolved: ResolvedThemeState;
  readonly themes: readonly RegisteredTheme[];
  readonly setFixedTheme: (themeId: string) => Promise<void>;
  readonly setFollowSystem: (enabled: boolean) => Promise<void>;
}
```

产品不再暴露 import/create/delete/repair 主题包入口。底层旧 repository 和 IPC 可以暂时存在用于兼容诊断，但不能作为新能力展示。

Feature 若需要 code editor/canvas 的当前配色，只读 `resolved.colorScheme` 或共享派生 token，不根据 Theme Pack ID 写分支。

## Failure Model

| Failure | Required behavior |
|---|---|
| Unknown or non-built-in theme ID | fallback by expected colorScheme, preserve invalid selection for diagnostics |
| Invalid built-in manifest | fail package startup in development; release validation must prevent shipping |
| Runtime variable application fails | restore previous resolved state, error feedback + diagnostic details |
| Presentation Profile unknown/unsupported | reject apply; do not guess fallback silently |
| Scene renderer missing | keep tokens, fall back to theme solid surface |
| User background decode fails | keep preference, show theme default surface and repair entry |
| OS scheme event during fixed mode | no theme change |
| OS scheme event during system mode | resolve mapped theme atomically |

## Tests

- Registry duplicate ID、unknown schema、missing tokens、invalid colors、fallback。
- Fixed/System resolution and OS event behavior。
- 非 built-in 历史选择不进入 registry，按颜色模式回退。
- First frame dataset and computed token match final state。
- Theme switch while Dialog、Menu、Composer、Terminal 和 Right Dock 处于开启状态。
- Scene manifests、scene renderer、主题缩略图和保护路由。
- Apply failure restores previous theme without unmounting page or losing focus。
- Web local storage failure and Desktop adapter failure produce productized feedback。
- macOS/Windows representative renderer uses the same Theme Pack ID and semantic tokens。

Cross-platform signed package、Windows DPI/high contrast and Desktop native user-background acceptance remain separate release gates.
