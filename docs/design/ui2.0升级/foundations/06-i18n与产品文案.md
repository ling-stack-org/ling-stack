# i18n 与产品文案

## Ownership

`@ling-stack/ui-react` 不导入 Web i18n。所有可见标签、close/dismiss label、错误和空态由
调用方传入。Web adapter 可提供常用翻译默认值。

## Product Copy

- 优先结果、影响和下一步。
- 不显示内部枚举、transport、adapter、slice 或 raw provider response。
- 技术详情进入折叠区，默认文案仍应可理解。
- 成功反馈短暂；阻塞错误持续到修复或关闭。
- 危险确认明确删除内容、保留内容和不可恢复后果。

## Runtime Error Localization

运行时错误必须在 Web 调用边界转换为结构化产品错误，禁止把 daemon、浏览器或供应商的
动态 `Error.message` 直接作为主文案显示：

- 严格按稳定错误码、HTTP 状态与 transport 类型、有限消息特征三阶段匹配；后续阶段不得覆盖前一阶段的判断。
- 主文案使用当前语言描述结果、影响和下一步；未知错误使用当前操作的本地化兜底文案。
- 原始响应保存在 `technicalMessage`，只进入默认折叠的“技术详情”，不作为 i18n key。
- `DomainError` 和局部操作结果必须分开承载产品文案与技术详情，不得通过一个 `message` 字段混用。
- 同一错误只保留一个反馈 owner；页面、对话框、行内反馈和 toast 不得重复显示。
- 对话框内操作返回局部结构化错误，不得通过比较本地化文案来识别一次新的失败。
- 远端操作已成功、后续本地清理失败时必须显示部分成功警告，不得把已完成的操作误报为失败。

Web 统一使用 `toProductError(error, t, context)` 完成上述转换。新功能不得新增直接展示
`error.message` 的路径；维护既有模块时按其反馈 owner 逐步迁移。

## Consistency

- 同一页面不得中英文混排，产品名和模型名除外。
- 中英文必须表达同一行动和后果，不只保持 key 数量一致。
- 删除 UI 时同步清理无引用 key。
- Tooltip 和 ARIA 名称也必须通过 i18n。

## Terminology

统一使用：模型工作台、AI 队友、Council Workspace、自动化、媒体任务、媒体生产、
Work Board、运行诊断、技能库、已归档项目。旧术语只能出现在历史文档或诊断详情。
