# 全局反馈消息迁移矩阵

## Purpose

本文档把当前 Web 中分散的页面提示、局部 Toast、`inline-error`、
`inline-success`、操作结果和 browser `alert()` 映射到 UI 2.0 的统一反馈系统。

这不是把所有消息都改成 Toast。目标是让每条消息在正确位置、持续正确时间，
并且不再由 Feature 自己定义样式、计时器和可访问性。

## Feedback Decision Contract

| Message class | Target primitive | Placement | Lifetime | Clear condition |
|---|---|---|---|---|
| 保存、复制、创建、导入、排队成功 | Toast `success` | 全局 top-center | `3000ms` | 自动；hover/focus 暂停 |
| 轻量信息，不影响下一步 | Toast `info` | 全局 top-center | `3000ms` | 自动或同 scope 替换 |
| 非阻塞警告 | Toast `warning` | 全局 top-center | `5000ms` | 自动或手动关闭 |
| 轻量错误，页面仍可继续 | Toast `error` | 全局 top-center | `6000ms` | 自动/手动；修复路径仍要 inline |
| 字段验证 | Field error / InlineFeedback | 字段下方 | 持续 | 输入改变或验证通过 |
| 行、卡、Inspector 对象操作失败 | InlineFeedback | 受影响对象附近 | 持续 | 重试成功、对象切换或显式关闭 |
| 页面加载、daemon、API Key、诊断 blocker | InlineFeedback | PageContent 顶部或对应 section | 持续 | refresh 成功或 blocker 解除 |
| loading/checking/saving/generating | Button/row/progress state | 发起操作处 | 操作期间 | promise settle |
| approval/waiting/stale/current status | StatusIndicator / InlineFeedback | 对象内 | 持续 | 业务状态变化 |
| 删除、撤销、覆盖等破坏决策 | Dialog | overlay | 用户决策前 | cancel/confirm |
| 技术证据、raw response、path/id/hash | Details / Inspector | 折叠详情 | 持续 | 用户关闭详情 |

### Non-Negotiable Rules

- 普通成功不使用 Dialog，不使用页面内常驻绿色条。
- 用户需要读取消息才能修复问题时，Toast 不能是唯一载体。
- Feature 不得用 `setTimeout` 管理 Toast 生命周期。
- 同一 scope 的连续成功、进度更新或重试结果替换旧 Toast，不堆叠。
- 页面切换不应清除仍在有效期内的全局 Toast；对象级 InlineFeedback 随对象卸载。
- 不允许 `globalThis.alert()`、`window.alert()` 或 Feature 自建 Toast viewport。

## Target Architecture

```text
Feature domain result
  -> apps/web/src/shared/ui/feedback adapter
     -> localized message + stable scope
        -> @ling-stack/ui-react ToastProvider / InlineFeedback / FieldError
```

- `@ling-stack/ui-react` 负责 viewport、stack、duration、pause、dismiss、ARIA 和 motion。
- `apps/web/src/shared/ui` 负责 i18n、Web 默认 scope 和现有 API 的兼容 wrapper。
- Domain 返回结构化结果，不导入 React、Toast 或 locale 文件。
- 当前 `apps/web/src/shared/feedback/LingToastProvider.tsx` 只作为 U2 迁移期兼容层，
  U13 前必须删除或变成无样式的 Web adapter。

Target event shape:

```ts
type FeedbackTone = "success" | "info" | "warning" | "error" | "loading";

interface FeedbackInput {
  readonly scope: string;
  readonly tone: FeedbackTone;
  readonly message: string;
  readonly durationMs?: number;
  readonly action?: { readonly label: string; readonly onSelect: () => void };
}
```

Scope 使用稳定语义，不使用随机 ID：

```text
profile:save
settings:personalization:save
skill:<skillId>:archive
provider:<providerId>:check
plugin:<pluginId>:install
channel:<channelId>:workspace-binding
conversation:<threadId>:copy
media-production:<projectId>:save
```

## Clearing And Dedupe Rules

| Situation | Required behavior |
|---|---|
| 用户连续点击保存 | 同 scope 替换，不堆叠，计时从最新结果重置 |
| loading 更新为 success/error | 原 Toast 就地 update，不创建第二条 |
| 对象被删除 | 清除对象级 InlineFeedback；删除成功 Toast 可保留到 duration 结束 |
| 切换 Tab/Inspector | 对象级 feedback 随所有者卸载；全局 Toast 不被误清除 |
| 输入值改变 | 清除已不再成立的字段错误，不清除与值无关的 daemon blocker |
| 后台状态自动恢复 | refresh/poll 确认恢复后清除 InlineFeedback，不额外弹成功 Toast，除非是用户发起的修复 |
| 相同消息高频重复 | 按 scope 去重；不以文案字符串作为唯一 key |
