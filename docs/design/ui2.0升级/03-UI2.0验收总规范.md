# Ling UI 2.0 验收总规范

## Definition Of Done

一个功能点只有同时满足以下条件才能标记 `verified`：

1. 使用目标共享 primitive，或有文档批准的领域组件理由。
2. 默认、交互、异步、错误和边界状态均已验证。
3. 中文与英文不串文案。
4. `ling-light`、`ling-dark` 均通过，且自定义 Theme Pack fixture 不破坏组件合同。
5. `1440x960`、`1280x800` 无横向溢出和操作挤压。
6. 键盘、焦点、ARIA 和 reduced motion 符合规范。
7. 对应 E2E 通过，真实浏览器截图已归档。
8. Browser console 无新增错误和可访问性警告。

Web `verified` 与 Desktop `release-ready` 分开记账。P9-EF 完成后可以关闭现有可达 Web UI 2.0 主线；Intel
macOS、Windows、packaged restart 和平台辅助技术证据只进入独立 Desktop 发布清单，不反向阻塞 Web 状态。

## Visual Acceptance

- 页面第一屏能识别对象、状态、主行动和需处理事项。
- 不出现重复标题、灰字说明墙、彩色状态堆叠或嵌套卡片。
- 同级按钮高度、图标基线和间距一致。
- icon-only 控件点击区域至少 `32px`，文字按钮不得被图标顶偏。
- 普通操作图标来自标准 Lucide 映射，尺寸、stroke 和 currentColor 符合 iconography 文档。
- Logo 与 favicon 路径、颜色、比例和绘制内容保持不变。
- 文本不遮挡、不竖排、不把操作推离容器。
- 列表和 Inspector 有最大高度或明确页面滚动责任。
- Dialog、Drawer、Popover 不超出 viewport，内容区内部滚动。
- 主行动唯一；次级和危险操作层级明确。
- 主题切换只改变 semantic tokens、批准 surface、artwork 和 Presentation Profile，控件
  geometry、Logo、图标、业务内容和布局不变。

## Interaction Acceptance

- Dialog：Esc、焦点锁定、焦点恢复、外部关闭和 busy 阻止关闭符合合同。
- Menu：键盘导航、关闭、disabled 和 danger 状态可用。
- Tooltip：hover 与 focus 均可触达，不承载完成任务所必需的信息。
- 自动聚焦 Dialog/Drawer 关闭图标时，第一次 Esc 必须关闭当前模态层；不得先消费一个关闭 Tooltip。
- Tabs：方向键、active、overflow 和内容切换稳定。
- Toast：不阻塞流程，成功自动消失，错误按后果决定持续时间。
- Feedback：短暂 success/info 只用全局 Toast；字段、对象、blocker 和修复路径保持 inline。
- Dedupe：同 scope 消息替换而不堆叠，loading 在原位更新为 success/error。
- Clear：每条 InlineFeedback 有所有对象和明确清除条件，不因无关页面操作消失。
- Field：label、description、error 和控件 id 正确关联。
- Loading：只影响发起动作的控件，不制造全页误导性 busy。
- Disabled：必须能解释修复路径，不能只有灰掉的按钮。
- Theme：Follow System 与具体 Theme Pack 是两个概念；System 不渲染为主题选项。
- Theme switch：不刷新页面、不丢焦点、不重置滚动、不关闭 Dialog/Drawer/Terminal。
- Theme failure：应用失败原子回退，不留下混合 token 或空白背景。
- Theme Studio：Quick/Generate/Advanced 进度绑定真实步骤，可取消、重试和恢复。
- Theme generation：UI screenshot 不能直接安装；模型输出必须经过 Compiler 和 verification。

## Motion Acceptance

- 点击后的 pressed/loading/disabled 反馈不改变控件尺寸，不重复提交。
- Dialog、Drawer、Menu、Popover、Tabs、Disclosure 使用标准 duration/easing。
- 动画中快速反向操作以最后输入为准，不闪失、不跳位、不丢焦点。
- Summary、Right Dock、Bottom Terminal 独立开关，打开 Dock 时 Summary 连续移动。
- 拖动中 transition 关闭，pointer 跟手；释放后尺寸受 min/max 约束。
- Tabs 切换不横向飞入，列表不逐项 stagger，streaming 不逐 token 动画。
- reduced motion 下取消 translate/scale/pulse/shimmer/smooth scroll。
- `transition: all` 为 0，最终 keyframes/animation/raw duration 满足迁移预算。

## CSS And Icon Acceptance

- CSS 加载符合既定 cascade layer 顺序，没有未分层第一方样式。
- Feature 不命中 `.ling-ui-*` 内部 selector，不出现主题组件级覆盖。
- 当前切片满足 CSS 行数、颜色字面量、`!important` 和 legacy class 预算。
- Feature CSS 新增颜色字面量为 0；颜色来自 tokens。
- 同一行动全产品使用同一个标准图标。
- `react-icons` 仅保留批准的语言/文件品牌场景。
- 不存在远程 Iconfont、PNG 操作按钮、emoji 或字符图标。
- `LingStackLogo.tsx`、favicon SVG/PNG 通过内容 hash 或明确 diff 检查保持不变。

## Theme Acceptance

- `ling-light` 和 `ling-dark` 是两个完整内置 Theme Pack，不互相继承补齐。
- System selection 根据 OS 外观解析主题；fixed selection 不随 OS 变化。
- 首个可见帧的 `data-ui-theme`、`data-color-scheme` 和 computed sentinel token 与最终状态一致。
- 内置主题覆盖全部 View、Settings、Overlay 和领域组件。
- 本地导入主题通过 schema、token、对比度、Preview 和 ZIP 安全验证；D1=A 下任何 runtime artwork
  必须拒绝且不得改变当前主题。
- Web IndexedDB 验收不等于 Desktop 原生持久化；后者必须有 app-data、原子 staging/rename、typed IPC、
  packaged restart 和 macOS/Windows 实机证据。
- 本地主题不包含 CSS、JavaScript、HTML、字体、远程 URL 或 Logo 替换。
- Web、macOS、Windows 使用同一 manifest/token 合同，仅 client surface adapter 不同。
- 不支持 blur/transparency 时使用不透明 fallback，不影响可读性。
- Feature CSS 中 `data-theme`、`data-ui-theme` 和具体 Theme Pack ID selector 为 0。
- Feature CSS 中 Presentation Profile ID selector 为 0；Profile 只由共享 presentation layer 消费。
- Quick mode 断网可用，不发模型请求。
- Generate mode 只有生图模型也能完成，不强制普通文本模型。
- Advanced mode 支持同一模型或不同 Planner/Artwork 模型，并使用严格结构化 plan。
- 生成主题不能包含 CSS、JS、HTML、selector、远程资源、Logo replacement 或 provider secret。
- Home、Conversation、Settings、Dialog 在四个 Profile 和所有目标 viewport 下可读。

## Desktop And PiP Acceptance

本节从 P9-EF 起属于独立发布门禁，权威状态见
[`release/01-Desktop跨平台发布验收清单.md`](release/01-Desktop跨平台发布验收清单.md)。

- Desktop main BrowserWindow 加载 shared Web UI，不存在复制的 AppShell/Settings/feature tree。
- first visible frame 的 Theme Pack、Profile 和 bootstrap tokens 与最终 renderer 一致。
- macOS traffic lights / Windows title bar 不覆盖 Sidebar、Header 或主行动。
- incompatible daemon 使用 native Retry/Quit，Retry 不杀死外部 daemon，Esc/Cancel 等价于 Quit。
- current-session Computer Use control 只出现在 owner conversation，channel/normal/teammate 高度一致。
- Show/Hide/Stop action hit area `>=32px`，失败反馈不改变 Header 高度。
- PiP 在 `320x200`、`420x263`、`480x300` 下无操作重叠或文字竖排。
- Live chrome 在 hover/focus 显示；无鼠标时键盘仍能发现全部行动。
- Hide、Close window、Stop Computer Use 保持三个不同语义。
- PiP 11 种状态使用产品化 label/detail/recovery，不显示 raw provider/capture wall。
- PiP 行为测试覆盖与视觉截图证据分别记账；当前 macOS arm64 的 14 scenario / 28 张
  Light/Dark 基线证明 11 状态视觉覆盖，但不能替代 Windows、high contrast、真实 AT 或签名包证据。
- PiP theme switch 不重建 BrowserWindow、React root 或 MediaStream。
- macOS/Windows 使用同一 geometry、icons、status 和 Theme tokens；平台只解释 chrome/material。
- reduced motion、reduced transparency、forced colors、Retina/DPI 和 multi-display 均有证据。
- Desktop auto-show preference 只在 capability 存在时显示；保存拒绝回滚，session-only 结果持续
  提醒重启风险，成功不制造常驻提示。
- Open task 在 renderer reload、较新 intent、目标 lookup 延迟、main-window recreation 下仍只打开
  最新 owner conversation；失败不停止 Computer Use。
- composer、approval、dock、terminal、modal、popover 出现/移动/消失时，PiP 避让不抢焦点、
  不覆盖主行动、不泄露 surface 内容。
- Windows Cua Driver provider health 默认层只有一个产品状态和修复动作；raw tool/schema/UIA/DXGI
  结果只在 Details/diagnostics。

## Reachable-State Checklist

每个 Function ID 至少登记：

```text
default
hover
focus-visible
active / selected
disabled
loading / queued / saving
empty / no-result
success / warning / error / stale
menu / popover / dialog / drawer
details / inspector
destructive confirmation
long content / overflow / scroll
ling-light / ling-dark / imported theme fixture
zh-CN / en-US
reduced motion
```

不适用状态必须在模块文档中明确写 `N/A`，不能空缺。

## Screenshot Protocol

- 路径：`evidence/<group>/<function-id>/<viewport>-<theme>-<state>.png`。
- 视口：`1440x960`、`1280x800`。
- 主题：`ling-light`、`ling-dark`；额外内置/导入主题使用 representative compatibility evidence。
- 生成主题：Quick、Generate、Advanced 各保留成功、失败和修复状态证据。
- 截图必须来自真实 Vite 页面和 mock/real daemon 支持的可达状态。
- 截图前记录分支、commit、URL 和数据夹具。
- 关键动效使用开始、中间、结束三帧或 Playwright 断言补充。
- 已 verified 页面不因非视觉代码变更重复截图。最终批次只为新增 changed-state 生成一次 evidence，普通 focused
  与 broad 回归不得覆写既有 PNG 或 metadata。

## Regression Suites

P9-EF 的 A-E 小切片只运行 focused；四个实现切片完成后，在 I 集成中将 broad 与 full 合并为一次非 Desktop
全量回归。不得在每个小切片重复运行完整 Playwright。

- Shell：`app.spec.ts`、`workspace.spec.ts`、`dark-mode.spec.ts`。
- Conversations：`channel.spec.ts`、`teammates.spec.ts`、`composer-token.spec.ts`。
- Settings：`settings.spec.ts`、`external-work.spec.ts`、`mcp.spec.ts`、Skill specs。
- Management：model、plugins、automations、councils specs。
- Work：media、media-production、work-board、runtime、approvals、profile specs。

### Parallel Playwright Port Isolation

- `apps/web/playwright.config.ts` 默认继续使用 `4174`，并允许通过 `LING_PLAYWRIGHT_PORT` 为每个并行
  Agent 分配独立 Vite 端口。
- 同一工作树并行运行 Playwright 时，各执行者不得共享端口；建议主线程使用 `4184`，其余 worker 使用
  `4194`、`4204`、`4214`，并在 metadata 中记录实际端口。
- 一个测试进程结束不得停止另一个执行者复用的 dev server。出现大批连续 `ERR_CONNECTION_REFUSED`
  时先按测试基础设施冲突处理，不把级联失败计为业务回退；修复端口隔离后必须重新运行受影响套件。
- `reuseExistingServer` 只允许复用当前执行者的相同端口，不是跨 Agent 共享服务的授权。

## Hard Stops

- Settings 内出现主应用导航。
- 功能页面直接导入 Radix。
- 为视觉迁移新增 API、状态机或数据库字段。
- 使用 localStorage 保存权威运行状态。
- 新增大面积硬编码白、黑或语义色。
- 新增远程 Iconfont、普通操作 PNG/emoji 图标或 Logo 近似替换。
- 新增未分层 CSS、Feature 覆盖 `.ling-ui-*` 或逃逸 z-index。
- 新增未登记 keyframe、raw duration/easing、弹跳/摇晃或不可打断的单向页面动画。
- 新增 browser `alert()`、Feature 自建 Toast viewport、反馈生命周期 timer 或页面常驻成功条。
- 将 API Key、daemon、字段验证、审批、生成失败或诊断 blocker 只放进会自动消失的 Toast。
- 将 Light/Dark 重新定义为 Theme Pack 内部双模式，或要求每个主题提供成对版本。
- 导入可执行 CSS/JS、远程主题资源、Feature 主题 selector 或 Logo 替换。
- 允许 Theme Pack 提供 Presentation Profile CSS、DOM、slot 坐标或未登记 Profile。
- 将模型生成的自由文本、token map 或图片直接标记为已安装主题。
- Quick 模式偷偷调用网络模型，或 Theme Studio 直接读取 API Key/secret。
- Desktop main/PiP 复制 shared feature UI 或在 Web feature 中直接导入 Electron。
- PiP 使用私有通用 Button/Menu 视觉、低于 32px hit area 或 Theme Pack 硬编码颜色。
- 视觉迁移改变 Hide/Close/Stop、approval、permission、capture provenance 或 release ACK 语义。
- 通过隐藏能力、删除诊断或伪造状态来达到视觉简洁。
- 只检查默认页面，不检查 Tab、弹窗和错误态。
