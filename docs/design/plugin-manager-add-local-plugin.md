# 插件管理新增本地插件

## Summary

插件管理需要同时承担“查看现有插件”和“添加受信任的本地能力”。第一版新增插件不是插件市场，
而是把用户明确配置的 MCP 连接包装成一个受管理插件。插件与 MCP 连接同时创建，默认停用，
只有用户显式启用后才获得运行能力。

## Product Flow

- 插件页顶部提供 `添加插件` 主操作。
- 点击后打开右侧抽屉，不离开插件列表。
- 用户填写插件名称、描述和连接方式：
  - `本地命令`：可执行命令和逐行参数。
  - `HTTP 地址`：streamable HTTP MCP 地址。
- 创建成功后关闭抽屉，新插件立即出现在列表中，状态为 `待启用`。
- 用户可以先检查连接，再显式启用。
- 插件详情中的 `查看 MCP 连接` 进入对应 MCP 设置页面。

## Table Contract

- 插件列展示图标、名称和一行简短描述，不再让名称单独占据整列。
- 状态列和操作列使用固定宽度，并在各自列内居中。
- 操作列标题与按钮组共享同一条水平中心线。
- 行高允许描述存在，但保持紧凑，目标为 58–64px。
- 只有当前主操作显示文字；检查、停用、详情继续使用带 tooltip 的图标按钮。

## Trust And Runtime Boundary

- 新增插件来源固定为 `trusted-local-preset`。
- 创建请求不能携带明文 secret；需要鉴权时后续在 MCP 设置中配置 secret ref。
- 新插件和关联 MCP 默认均为停用。
- 启用插件只启用已关联 MCP，不绕过 MCP 检查、工具同步、审批策略或队友绑定。
- 插件检查必须检查真实 MCP 连接；不能只返回“元数据可用”。

## API Contract

`POST /plugins?cwd=...`

请求包含：

- `displayName`
- `description`
- `transport`

响应返回创建后的 `ManagedPluginView`。daemon 负责生成插件 ID 和 MCP server ID，持久化插件描述、
贡献关系和禁用状态。

## Non-goals

- 不支持 GitHub、npm、远程 zip 或任意脚本下载。
- 不提供公共插件市场、自动更新或第三方签名体系。
- 不在新增抽屉中配置 secret、工具审批或队友绑定。
- 不把普通 MCP 服务自动伪装成插件；只有从插件新增流程创建的连接才建立插件关联。

## Acceptance Criteria

- 插件列表名称下方可见描述。
- 操作列宽度稳定，标题与按钮组对齐。
- 用户可以创建本地命令或 HTTP MCP 插件。
- 创建后插件与 MCP 均保持停用，并可从插件页检查、启用和查看详情。
- 重复点击提交不会产生并发重复记录。
- 1280、1440、1920 桌面宽度无横向溢出。
