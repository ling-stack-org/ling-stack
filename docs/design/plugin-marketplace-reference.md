# Ling 插件商店设计稿：参考与结论

## 参考观察

- **DSh**：插件是左侧一级入口，下面直接列出已安装插件；入口和列表是主结构，用户不需要先填写插件源地址。
- **Codex**：插件安装采用 store/list 信息层级，能够区分本地插件、远程主机插件、云端插件和 marketplace；列表同时给出名称、来源、描述、状态与安装动作，并明确加载、错误重试和空列表状态。

## 本稿的收敛方向

- 页面只保留“已安装 / 未安装”两个 Tab，不再显示来源侧栏、本地插件入口或管理表格。
- 主区域使用有限宽度的单列布局，Tab 与搜索框位于同一工具栏；不重复显示窗口标题和官方源说明。
- 已安装 Tab 的每个插件使用启用/停用开关；未安装 Tab 的每个插件使用安装按钮。
- 官方目录按游标分页，首次请求 50 条，滚动接近底部时继续请求下一页并追加，避免一次性渲染完整目录。
- 无源时不渲染假插件，只显示原因和“重新加载”；已经安装的插件可继续使用。
- 安装、启用和停用动作留在对应行内，操作期间只锁定当前行。
