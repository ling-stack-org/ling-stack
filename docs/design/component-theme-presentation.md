# 共享组件主题外观合同

状态：长期组件外观与开发接入合同；适用于所有新增或修改的主题、共享组件与 Web/Desktop 模块。Codex 于 2026-10-28 创建并补充开发规范；本轮实施顺序见[实施方案](component-theme-presentation-implementation-plan.md)。

## 问题与目标

本次改造前，组件已共享结构，但页面仍写死 Composer 圆角、覆盖阴影；小按钮与大 Shell 共用阴影，背景材质计算未使用全部主题基准。此前“完成”只证明背景、基础配色与功能检查，不能代表组件精修完成。

统一为“基础默认值 → 官方主题参数 → 共享组件消费 → 页面布局”。页面不得重定义 Composer 外观；普通会话、频道和私聊使用同一套外观与状态规则。

## 所有权与参数

| 所有者 | 职责 |
|---|---|
| ui-react 默认值/官方主题 CSS | `--ling-control-*`、`--ling-composer-*`、`--ling-navigation-*`、`--ling-card-*`、`--ling-overlay-*`、`--ling-message-*`；默认值保证其他官方主题可用，三主题只覆写参数 |
| ui-react 组件 | Button/Input、Menu/Popover/Dialog/Toast、DataRow/Table 消费各自圆角、边界与阴影；小控件不再使用 Shell 阴影 |
| conversation-ui-react | 唯一 Composer 默认/focus 外观和工具栏材质；共享消息、引用、代码读取主题参数 |
| Web 页面 | 位置、宽度、间距和密度；导航和管理页在既有入口消费参数，无按 theme ID 分叉的业务组件 |
| 背景 resolver | 开放画布按 ambient × (1 − 有效可见度) 染色；承载文字的面板做局部对比度保护；设置预览与真实背景共用计算 |

参数仅为应用控制的 CSS 展示变量，不扩展主题包、API、存储 schema 或用户可执行 CSS。

## 新组件必须能够被主题使用

1. 优先复用 `ui-react` 的 Button/Input/Menu/Dialog/Table 等控件；会话复用 `conversation-ui-react`，不得为新模块复制一套基础控件或 Composer。
2. 新的通用交互/外观放入共享包；业务请求、权限、路由和数据仍由 Feature 拥有。组件接收语义化 `variant`、`tone`、`size` 与回调，不接收 `themeId`，不读取主题选择或业务 store。
3. 组件外观优先消费已有参数。确需新增时，在 `component-tokens.css` 提供完整默认值和语义 fallback，在共享组件 CSS 中建立唯一消费入口，并更新本合同的参数表。主题未声明新参数也必须可读、可操作。
4. 主题参数允许控制颜色、边框、圆角、局部阴影、工具栏材质和选中标记；控件高度、命中区域、字体、布局、导航、图标、Logo、交互与业务状态保持稳定。不能用“所有 geometry 固定”禁止已批准的组件圆角，也不能借主题改变布局尺寸。
5. 默认、hover、pressed、selected、focus-visible、disabled、loading、error 使用同一组件实现。语义错误/警告不变成主题装饰色；disabled 不产生可点击反馈，forced-colors 下焦点仍可见。

| 组件用途 | 应消费的外观参数 | 实现入口 |
|---|---|---|
| Button/Input 等基础操作 | `--ling-control-bg/border/radius/shadow`、语义 action/status 和 focus | `ui-react/styles/controls/` |
| 会话输入区及工具栏 | `--ling-composer-*`、`--ling-bg-composer`、`--ling-border-focus` | `conversation-ui-react/styles/composer/` |
| 导航/快捷入口 | `--ling-navigation-*`、`--ling-shortcut-*` | 共享导航外观与首页布局槽 |
| 列表/卡片/表格 | `--ling-card-*`、`--ling-row-*`、`--ling-table-header-bg` | `ui-react/styles/feedback/data-display.css` 与领域容器 |
| Menu/Popover/Dialog/Toast | `--ling-overlay-*`、`--ling-dialog-radius`、`--ling-menu-item-radius` | `ui-react/styles/overlays/` 与 `feedback/toast.css` |
| 消息/引用/代码 | `--ling-message-*`、`--ling-code-radius`、语义代码色 | `conversation-ui-react/styles/blocks/` |

参数的精确拼写与默认值以 `packages/ui-react/src/styles/component-tokens.css` 和 foundation tokens 为准。新增参数不要求所有主题复制一遍默认值；它们继承共享默认值，不能继承另一主题的 manifest。

## 新模块开发接入

模块设计与实施方案必须包含“主题适配”小节，至少回答：

- **复用哪些组件**：列出基础控件、列表/表格、浮层、反馈和会话组件的实际入口；领域组件说明为什么需要独立所有权。
- **消费哪些参数**：列出已有组件/语义参数；新增参数写明默认值、消费组件和需要覆写的主题。禁止页面内颜色、圆角、阴影硬编码，以及按 theme ID 或 dark/light 修补共享外观。
- **背景是什么表面**：通过 `AppPresentationSurfaceBridge` 与共享 surface policy 分类。普通首页/频道/会话/管理工作区允许环境背景；设置、诊断、审批和媒体画布等受保护工作流保持实底。布局、feed、消息对齐轨道透明，正文/代码/输入/表格内容/浮层提供阅读保护；允许背景的普通工作区不得直接给页面根元素铺不透明底，也不得在 Feature 自己创建背景播放器。
- **如何验证**：列出可达状态、主题切换、背景开关/回退和截图位置；证据要绑定当前源码，不能引用历史截图宣称新模块适配完成。

页面可定义 grid、宽度、间距、密度和滚动边界；不能通过传入 className 或覆盖 CSS 变量重新拥有共享组件的背景、边界、圆角、阴影及 focus。发现缺失能力应补共享语义参数或变体，而不是增加更高优先级 selector 或 `!important`。

## 新主题制作

1. 先确定背景与组件的配色、形状、材质、层次、交互状态矩阵；交付内容包含导航、Composer、主次操作、消息/代码、列表/卡片及浮层，不能只提供壁纸。
2. 在 `ui-react/src/theme/built-ins/` 定义完整、通过 validator 的语义 manifest，接入内置 registry；官方资源与缩略图按[主题系统](ui2.0升级/themes/README.md)登记。
3. 在 `styles/themes/built-in-themes.css` 的主题选择器中集中声明组件参数，值与 manifest 的语义颜色保持一致。只有共享主题层可以匹配官方 theme ID，Feature 和组件不出现具体主题分支。
4. 当前组件参数是应用控制的 CSS 合同，未加入 `LingThemePackManifest` / `LING_THEME_CSS_VARIABLES` 的序列化字段。不能把任意 CSS 或组件参数放进 JSON 并宣称运行时会自动支持；确需扩展数据协议时另行同步 types、validator、mapping、bootstrap/回退与测试。
5. 新主题不改变现有用户数据、模型配置、媒体偏好或业务能力；当前产品仍只提供内置主题，不开放主题包导入或生成入口。

## 新增模块与主题的验收门槛

- 新模块对六套内置主题都做基础可读性与布局检查；视觉组件修改覆盖 Light/Dark、Breeze 以及 Night/Ocean/Journey，不能只测当前开发者选中的主题。
- 所有新增可操作控件覆盖键盘焦点、hover/pressed/selected、disabled/loading/error；不可达状态注明原因，不伪造业务成功。
- 使用同内容与视口验证主题切换后无旧样式残留、草稿/焦点/滚动保持；跨普通会话、频道和私聊的共享控件比较实际 computed style。
- 背景展示与隐藏时都可读，受保护表面不透出背景；检查强制颜色、减少动态/透明度和窄窗回退。平台、语言与视口沿用[总验收规范](ui2.0升级/03-UI2.0验收总规范.md)，不据 Web 截图推导原生包验收。
- “参数已接入”“功能/可读性验收通过”“主题美术确认”分别记录；源码或自动测试不能替代视觉复核。截图至少覆盖模块主状态和有变化的交互状态。

以上为开发与评审要求。已有 lint/test 只覆盖其明确定义的规则，并不自动证明所有新模块合规；新增组件或模块必须补对应的交互/视觉证据。

### 样式生效顺序

`styles/index.css` 使用 CSS layer：`ling.tokens.base` 提供基础及组件默认值，`ling.tokens.theme` 提供官方主题参数。共享组件读取变量，不为每个主题复制组件 CSS。`applyResolvedTheme` 切换根元素 `data-ui-theme`；匹配的主题参数覆盖默认值，未定义的参数自动沿用默认值。切到其他主题后，前一主题选择器不再匹配；回到官方主题时也会移除历史导入/生成主题遗留的运行时语义变量，这不开放导入或生成入口。

例如 Composer 默认圆角 14px，Night 覆写为 10px，Ocean 为 18px，Journey 为 14px；同一组件同时读取对应的背景、边界、阴影及焦点参数。页面保留位置/宽度/间距；禁止用页面内的硬编码外观重新盖掉这些参数。背景本身由独立的连续媒体层展示，材质 resolver 基于主题值执行局部阅读保护，禁止为保护首页标题而反向加浓整屏蒙层。标题以语义底色字形 halo 保护，100% 时开放画布保留原图。

背景素材按用户明确指定落实；配套 UI 的绿色参数保持。实施顺序与停止条件见实施方案的 B0–B5，整体 UI 美术与原生发布验收仍独立记录。

## 边界与验收

- 保留已确认背景、原 Logo、布局操作位置、控件高度、模型/会话/工作区数据和背景偏好；不生成素材、不加点击特效、不提交远端。
- 正文、代码、设置、浮层保持可读；布局轨道保持透明。content 材质基准可由 resolver 提高不透明度保护阅读；ambient 仅用于开放画布染色，随可见度递减，不能用于整屏对比度保护。
- 三类 Composer 默认/focus 的圆角、背景、边界和阴影一致，首页只保留布局差异。
- 相同夹具、内容和视口截图；遮住背景仍能从 Composer、导航、按钮和菜单辨认三套风格。
- 覆盖首页、普通/频道/私聊、管理页、设置和弹层，回归 Light/Dark 及其他官方主题，核对窄窗、强制颜色、减少透明度和切换无残留。
- 包检查和隔离浏览器通过后，复用实际 5173 浏览器检查交互、截图和控制台；夹具通过不等同真实推理、签名 Desktop 或用户美术定稿。
