# Original Office packaged bootstrap checkpoint — 2026-10-07

This is a source implementation checkpoint, not T6 completion, a release,
actual default Daemon startup acceptance, or clearance to merge the cumulative
PR. Full Access and other unrestricted same-user processes are outside the
controlled-process isolation guarantee.

## One original same-process packaging lane

The first lane is fixed to macOS arm64, `unsigned_dev`, the default Electron
Builder ad-hoc signer, and ZIP plus DMG. It preserves the original Cua package
CLI preparation and cleanup contract. Provider-bearing unsigned development
packages are explicitly unsupported: the existing custom signer can return
`signed: false` and does not fall back to Builder's default signer.

```text
fixed independent source/packaging review
  → original fresh native build
  → fixed ad-hoc pre-sign and strict verification
  → original final-byte and exact-source publication
  → fresh codesign publication and fresh Daemon bundle
  → same-process awaited Builder with active original publication
  → afterPack exact copy / exact absolute addon signIgnore
  → afterSign deep/strict verification and unchanged bytes
  → each actual ZIP/DMG extraction, unique product App and readback
  → awaited extraction cleanup
```

The publication is an opaque private in-memory token, not a JSON receipt,
environment value, Core grant, runtime permission or source issuer. Forged,
cloned, stale or replaced staged inputs cannot select a build. File identities
and bytes are pinned before the stage moves to its final location; a later
snapshot cannot legitimize changed outputs. Active provenance and the scoped
Cua environment remain in place across the full awaited Builder invocation.
Concurrent or reentrant packaging fails closed and the original environment is
restored on every completion path.

The fixed review covers the exact fifteen native source inputs, packaging
inputs, compiler/SDK/header pins, runtime tuple and signing profile. Missing,
pending, stale or changed review is rejected. No production approved row has
been generated by this checkpoint. A build result cannot approve its own
source or packaging. Ordinary development bundling retains the no-publication
sentinel. `package:mac` uses the fixed lane and currently stops at the missing
review gate; this checkpoint must not be described as a usable final package.
Windows packaging is unchanged.

## Resources and original CLI bootstrap

Office resources live only in macOS `extraResources`; the stage and temporary
stage directories are excluded from `app.asar`. The intended resource closure
is the addon, build manifest and exact source inputs, with no foreign leaves or
empty directories. Runtime discovery has no caller path/configuration option:
it derives the same App from the actual executable, validates the embedded
literal and Electron runtime tuple, and uses bounded original readonly FD
reads with identity and EOF fences.

The CLI uses the original fixed codesign actor to verify the same App, then
revalidates its resources and returns only the typed three-field artifact
selection to the existing default Store/Supervisor. The primitive native facts
remain `packaged: false`, `distributionSignature: not_verified` and
`coreSafe: false`; neither build pins nor a codesign callback promote them.
The local development source root remains separate and exceptions do not
silently fall back to it.

## Hook and failure boundaries

Office checks run even when Cua has no staged provider/state. The original Cua
hooks remain awaited, and neither Office nor Cua errors are converted into
success. Signing ignores preserve unrelated rules and add only the escaped,
anchored absolute path of the actual addon after its bytes have been checked;
overlapping broad ignores are rejected.

Real ZIP and DMG completion events each keep their own artifact identity,
extraction, expected unique product App, verification and cleanup. Metadata
companion blockmaps are not App archives and must retain the original strict
Cua companion predicate without becoming successful Office evidence. App
candidate detection is case-insensitive, while the expected product path is
exact. Verification and cleanup failures preserve both original causes,
including falsy JavaScript rejection reasons.

The existing DMG extractor has bounded detach/force fallback and cleanup. It
does not yet have the ZIP extractor's equivalent initial mountpoint inode
guard. The emitted Daemon CLI has not yet been retained as original post-bundle
byte pins, and the new Office checks do not parse the final `app.asar` to prove
its CLI/literal closure or exclude unpacked/second Office copies. Independent
review also identified missing authored codesign/bootstrap dependencies in
the packaging digest set; the codesign native-source review is not a substitute
for that packaging closure. Both are approval-before-build gaps to implement
next. No production approved row exists, so this checkpoint does not enable
the incomplete route. These are not guarantees supplied by synthetic fixtures.

from genuine native loader conformance. Fresh source builds and raw RED/GREEN
logs are retained in the local continuation ledger. Neither a targeted GREEN
nor a callback invocation proves real compilation, signing, Electron package
identity, MCP product success or GUI acceptance.
