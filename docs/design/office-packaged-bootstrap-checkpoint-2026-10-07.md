# Original Office packaged bootstrap checkpoint — 2026-10-07

This is a source implementation checkpoint, not T6 completion, a release,
actual default Daemon startup acceptance, or clearance to merge the cumulative
PR. Full Access and other unrestricted same-user processes are outside the
controlled-process isolation guarantee.

## One original same-process packaging lane

The first lane is fixed to macOS arm64, `unsigned_dev`, the default Electron
Builder ad-hoc signer, and ZIP plus DMG. It preserves the original Cua package
CLI preparation and cleanup contract. Provider-bearing unsigned development
packages are explicitly unsupported: the existing custom signer can return
`signed: false` and does not fall back to Builder's default signer.

```text
fixed independent source/packaging review
  → original fresh native build
  → fixed ad-hoc pre-sign and strict verification
  → original final-byte and exact-source publication
  → fresh codesign publication and fresh Daemon bundle
  → same-process awaited Builder with active original publication
  → afterPack exact copy / exact absolute addon signIgnore
  → afterSign deep/strict verification and unchanged bytes
  → each actual ZIP/DMG extraction, unique product App and readback
  → awaited extraction cleanup
```

The publication is an opaque private in-memory token, not a JSON receipt,
environment value, Core grant, runtime permission or source issuer. Forged,
cloned, stale or replaced staged inputs cannot select a build. File identities
and bytes are pinned before the stage moves to its final location; a later
snapshot cannot legitimize changed outputs. Active provenance and the scoped
Cua environment remain in place across the full awaited Builder invocation.
Concurrent or reentrant packaging fails closed and the original environment is
restored on every completion path.

The fixed review covers the exact fifteen native source inputs, packaging
inputs, compiler/SDK/header pins, runtime tuple and signing profile. Missing,
pending, stale or changed review is rejected. No production approved row has
been generated by this checkpoint. A build result cannot approve its own
source or packaging. Ordinary development bundling retains the no-publication
sentinel. `package:mac` uses the fixed lane and currently stops at the missing
review gate; this checkpoint must not be described as a usable final package.
Windows packaging is unchanged.

The independent packaging digest now uses a focused fixed-input data module:
33 explicit roots, 1199 unique inputs, including the conservative authored
runtime graph, helper native-source inventory, license, and atomic publisher
compiler input. The source-review frame is bounded at 256 KiB; the separate
runtime fifteen-source literal remains bounded at 32 KiB. A graph change needs
an explicit review of this fixed list. Builds do not discover, regenerate,
approve, or refresh it. Authored coverage is not vendor/toolchain/OS approval
or proof that generated `dist` matches the reviewed source.

## Resources and original CLI bootstrap

Office resources live only in macOS `extraResources`; the stage and temporary
stage directories are excluded from `app.asar`. The intended resource closure
is the addon, build manifest and exact source inputs, with no foreign leaves or
empty directories. Runtime discovery has no caller path/configuration option:
it derives the same App from the actual executable, validates the embedded
literal and Electron runtime tuple, and uses bounded original readonly FD
reads with identity and EOF fences.

The CLI uses the original fixed codesign actor to verify the same App, then
revalidates its resources and returns only the typed three-field artifact
selection to the existing default Store/Supervisor. The primitive native facts
remain `packaged: false`, `distributionSignature: not_verified` and
`coreSafe: false`; neither build pins nor a codesign callback promote them.
The local development source root remains separate and exceptions do not
silently fall back to it.

## Hook and failure boundaries

Office checks run even when Cua has no staged provider/state. The original Cua
hooks remain awaited, and neither Office nor Cua errors are converted into
success. Signing ignores preserve unrelated rules and add only the escaped,
anchored absolute path of the actual addon after its bytes have been checked;
overlapping broad ignores are rejected.

Real ZIP and DMG completion events each keep their own artifact identity,
extraction, expected unique product App, verification and cleanup. Metadata
companion blockmaps are not App archives and must retain the original strict
Cua companion predicate without becoming successful Office evidence. App
candidate detection is case-insensitive, while the expected product path is
exact. Verification and cleanup failures preserve both original causes,
including falsy JavaScript rejection reasons.

The Office lane bundles with esbuild `write: false` and immediately copies its
unique returned output bytes before any later publication read or path capture.
Only those private bytes can be staged to the fixed CLI, with bounded writes,
exclusive temporary creation, fsync, hash and original-inode readback. Staging
and cleanup failures retain both causes, including falsy rejection values;
cleanup refuses a replaced temporary inode. Existing valid output directories
remain supported. The bundle lock is acquired before
native or codesign publication, so a rejected concurrent build cannot replace
either publication. Private emitted pins are keyed by original publication
identity; callers receive no bytes, receipt issuer or reconstructable token.

All three Office hooks, including each final extracted App, now compare the
actual `app.asar` CLI to those original hash/size pins. CLI links, unpacked CLI,
Office-named entries or links to the Office stage, and same-size renamed copies
of the original addon in packed or unpacked trees are rejected. Header bytes,
entry count, nesting, duplicate candidates and candidate bytes have fixed
budgets. Header caches are cleared and original archive/tree identities fenced
before returning. Third-party ASAR APIs reopen paths: these checks are byte
selection evidence, not retained-original-FD custody or malicious same-UID
isolation. Exact CLI byte comparison includes the injected literals; it does
not prove reviewed source/generated-output equivalence.

The DMG extractor now captures its first host parent/source inode pins, checks
the actual native uint64 hexadecimal wire format, and secures that same
directory before attach. It does not compare the mounted volume root with the
hidden host directory. After detach, only the exact original empty host
directory may be removed through the identity-bound native operation. A lost
identity is not refreshed and does not fall back to path-only deletion.
Retry, concurrent cleanup, detach/force fallback and both failure causes are
preserved. Partial/force-attach OS behavior and original attachment ownership
are still not proven by these guards.

A real one-normal-detach probe using an old local image observed the host
inode restored and the image SHA256 unchanged. It also exposed a separate
defect: `hdiutil attach` may update its checksum-cache attribute
even with a read-only mounted volume, changing the host image ctime. Passing
the original final DMG directly to it conflicts with the outer immutable
artifact fence. The solution must consume a private, exclusive, original-FD
byte snapshot and keep the original artifact's complete identity/ctime fence;
removing ctime checks or disabling checksum verification is not the solution.
The following input-snapshot increment implements this chain in a focused
filesystem module. The original readonly `O_NOFOLLOW` FD, complete metadata
including ctime, and streamed SHA256 remain fixed. An exclusive mode-0600
private copy has a 4 GiB byte bound, 64 KiB buffers, explicit-position partial
I/O and bounded attempts, fsync and exact hash readback. Only its pathname
reaches hdiutil. Snapshot ctime alone may change; original inode/type/owner/
mode/link-count/size/mtime and payload pins do not refresh.

Public verification and cleanup serialize, concurrent cleanup coalesces,
and the first terminal cleanup attempt closes each owned handle exactly once
even on failure. After failed detach, release-only closes handles without
deleting the potentially mounted backing image. Recovery retries retain
fixed pins and sticky validation failures; they never reopen or manufacture
fresh validation. Cleanup retains falsy causes and precise residue when an
initial identity exists. A root allocated before first identity acquisition
is reported, not removed by pathname alone. Office rechecks its original full
artifact identity after awaited cleanup before reporting success.

Snapshot leaf pins are checked in JS before bounded native tree removal;
the current native wire carries parent/root pins and count/size, not a fixed
leaf pin. This is not arbitrary Full Access or malicious same-UID race-free
isolation. Force/partial attachment and original attachment ownership remain
separate unverified gates.
The original probe ended RED, not whole-probe GREEN; its separately verified
host-inode and unchanged-byte observations do not constitute package acceptance.

Toolchain/vendor review, generated-output freshness and real final package
acceptance remain separate gates. No production approved row exists, so this
checkpoint does not enable the incomplete route. Synthetic fixtures do not
supply these guarantees.
